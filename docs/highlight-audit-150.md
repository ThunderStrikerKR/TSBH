기준 d407172414b3df8986dfc4080e3a4dcb45c798e3. 147차의 CI 검사 유지. 일반 버튼 및 처리중 주문의 고정 버튼에서 기본 stroke와 별도 하이라이트 overlay가 중첩됨을 소스로 확인하여 단일 표면으로 통합. 원터치 값 여백과 원문 블록 geometry를 highlight 모듈에 위임. 기존 4pt 값 여백, 4pt 원문 곡률, 6pt 일반 컨트롤, 5pt 내비게이션/고정 버튼, 4pt 카카오톡 버튼 유지.

표 선택 행의 행 구분선과 선택 outline, 수량 입력의 native focus와 추가 outline, 필수 입력과 원문/원터치 강조의 중첩, 카드 외곽선과 상태 stripe는 후속 실제 렌더링 검수 대상. 구조 구분선이나 의미가 다른 stripe를 임의 삭제하지 않음. 전수조사 완료 또는 Windows PASS로 판정하지 않음.

## 후속 확인 및 패치

- 공통 드롭다운 트리거, 달력 이전/다음, 발송지 토글: 명시적 기본 stroke + 별도 호버 overlay 제거, native 단일 frame 사용.
- 공통 표 선택 행: 일반 하단 행 구분선은 선택 outline으로 대체, 열 구분선 유지.
- 주문 배송 미리보기 행: 선택되지 않은 linked preview의 일반 외곽선 + 파란 외곽선 중복 제거. 선택 상태 우선 순위 보존.
- 수취인 원문 연결과 원터치 강조는 `!active`로 서로 배제되는 것을 확인. 수량 stepper의 공통 외곽선/포커스 및 필수입력 경고의 상태 합성, 달력 날짜 셀의 선택/오늘/호버, 카드 stripe는 별도 검증 필요.

## 150차 후속 Q1 — 상태별 우선순위

공통 States::resolve: 필수 입력 > 선택 > 원문 연결 > 원터치 검토 > 포커스 > 호버. 달력은 기존 날짜 선택색을 유지하고 native 단일 표면을 사용. 수량 stepper 외곽선은 포커스 여부를 자식의 반환값으로 받아 한 번만 렌더링. 거래처 선택 행은 선택/호버 상태를 공유 렌더러에서 결정하며 선택은 주황색, 일반 행은 기존 호버색 사용. 카드 상태 stripe는 구조 외곽선과 둥근 모서리 안쪽에 위치하며 선택 상태를 preview보다 우선. 필수 입력의 수취인/품목/운임/헤더 전체 통합은 후속 변경 필요. Windows/CI PASS 미판정.

수취인 5개 필드 및 품목 3개 필드의 필수 여부/편집 여부를 렌더링 전에 전달. 빨간 오류는 원문/원터치 강조와 상호배제하며, 편집 중에는 실제 편집기가 오류 배경과 외곽선을 소유. 수량, 금액, 연락처 편집의 입력값과 네이티브 caret 경로 유지. 운임 및 추가 버튼의 기존 사후 오류 강조는 별도 이관 필요.

운임/선착불/발송지 및 상품 추가/VAT/복사 버튼도 강조 상태를 실제 렌더러에 전달. 필수 운임은 원터치보다 우선, 편집기만 필수/검토 표면을 렌더링. 상품 추가 오류와 원터치 버튼 사후 덧칠 호출 제거. 실제 렌더링 및 CI 결과 미확인.

정적 감사의 과거 raw rect_stroke/사후 preview 호출 필수 조건 및 수량 외곽선 소유자 경로를 새 계약으로 갱신. 접수/공통 접수의 사후 오류·원터치 덧칠 재도입 검사 3개 추가(실행 미검증). 기존 금액 편집 회귀 테스트의 호출 인자 동기화. 정적 검사 자체의 실제 실행 결과와 Windows 렌더링 증거는 미확보.
