## 판정 기본 원칙

1. 제주특별자치도는 직원 요구에 따라 **전역 자동 체크 후보**. 제주시·서귀포시 전체.
2. 군산시는 **옥도면에 한정**한다. 군산시의 다른 동은 자동 체크하지 않는다.
3. 옥도면 안에서도 신시도·무녀도·선유도·장자도·야미도와 같은 **연륙도서 지역은 직원 확인(review)**으로 분류한다. 2025년 공정위 시정 이후 예전 목록을 확정 운임으로 사용하지 않는다.
4. 신안군 전체를 무조건 체크하지 않는다. 압해읍은 가란리·고이리·매화리만, 지도읍은 선도리·어의리만, 증도면은 병풍리만 자동 후보. 연결 도로가 있는 읍·면은 review.
5. 여수시 화정면의 **백야리 제외**, 인천 옹진군의 **영흥면 제외**를 다른 포괄 규칙보다 먼저 판정한다.
6. 동일 시군구나 우편번호만으로는 부족하다. `길`·`로`·번지·건물명은 지역 목록에 채택하지 않지만, **일부 리만 해당하는 곳은 반드시 리까지 유지한다.** 하위 지명이 불확실하면 자동 체크하지 않고 review로 표시한다.
7. 주소의 행정구역 처음 부분만 비교한다. 발주원문 중간의 상품명·건물명에 우연히 등장하는 지역명과 부분 일치로 체크하지 않는다.
8. `auto`는 **직원 확인을 전제로 한 초기 체크 제안**, `review`는 체크하지 않은 상태에서 확인 요청, `normal`은 명시 예외, `unknown`은 근거 불충분을 뜻한다.
9. 사용자가 직접 체크 또는 해제하면 주소를 바꾸기 전까지 수동 선택이 우선해야 한다. 같은 주소에서 새로고침·재계산마다 체크를 덮어쓰면 안 된다.
10. 운임 계산은 **기준 운임 × (도서/산간 체크 ? 2 : 1)**이다. 기준 운임이나 저장된 금액에 선행해서 2배를 적용하지 않는다. 이 배율은 사용자 지정 업무 규칙이며 외부 출처의 확정 도선료와 동일하다는 뜻이 아니다.

## 지명 정규화·주의사항

- `전라북도` ↔ `전북특별자치도`, `경기도` ↔ `경기` 등의 주소 머리글 변형을 처리한다. 법정 주소의 나머지 토큰을 모호하게 부분 일치시키지 않는다.
- 외부 출처에서 `웅진군`으로 오기한 이름은 실제 `옹진군`, `중도면`은 `증도면`, `근홍면`은 `근흥면`을 기준으로 정규화한다.
- 로젠 실운임은 기후·중량·부피·연륙 상황 및 계약에 따라 달라질 수 있으므로 이 지역 데이터는 **추가 청구 확정 근거가 아닌 직원 검토 지원 자료**다.
- **2026-11-19 패치:** 지역 데이터 + Rust 감지 → 수취인별 `도서/산간` 체크박스 → 운임 UI/배송 건 청구/결제·VAT·이력/실운임 검증 연결. 최초 자동 감지 대상은 체크가 켜지고, 직원이 해제하면 1배·다시 체크하면 2배. 자동 감지는 수취인 주소에 종속되며 주소가 바뀔 때 다시 평가한다. 자동 감지가 확실하지 않은 `review` 지역은 체크 없이 파란 직원 확인 안내만 띄운다.
- **데이터 계약:** `Recipient.remoteDelivery = {address,checked,manual:true}`은 직원의 선택이며, 같은 주소에서 Rust 재계산·탭 변경에 의해 덮어쓰지 않는다. 새로운 자동 체크는 Rust 재조정 단계에서 `manual:false` 스냅샷으로 보관한다. 변경 이전에 이미 처리 단계 1 이상/이관/확정된 주문은 기존 금액을 보존하도록 `legacy:true,checked:false` 스냅샷을 남긴다.
- **기준/적용 운임 분리:** 운임 추천의 `baseRecommendation`, 배송 건 `charges`, 수취인 수동 `shippingCharges`는 **기준 운임**이다. 적용 운임은 `checked ? 기준 운임 * 2 : 기준 운임`. 표시·청구·입금 안내·부가세·배송 완료 증빙에 같은 Rust 계산을 적용한다. 택배 실제 출고 비용 이력은 기록하되 도서산간 실제금액을 일반 상품 운임표의 활성 조합으로 재사용하지 않는다.
- **직원 수동 운임:** 화면 입력창은 적용 운임을 표시한다. 체크된 상태에서 직접 금액을 입력할 때는 저장할 기준 운임을 `입력 금액 / 2`로 계산한다. 원 단위 정수 기준 운임을 유지하기 위해 홀수 적용 운임은 저장하지 않고 안내한다. 착불 및 운임 면제의 청구 운임은 0원 유지.
- **검증 상태:** 업무 소스·정적 회귀 계약 및 Rust 단위 테스트 소스에 반영. 실제 Rust `cargo test`, TypeScript `npm test` 및 Windows UI 실행은 이 세션의 환경에서 실행하지 못했으므로 통과 판정 보류.
