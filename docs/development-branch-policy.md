# TSBH 브랜치 운영 규칙 — 2026-11-16

## 기준 브랜치

- **`main`은 유일한 신규 개발 기준선이다.** 2026-11-16 PR #24 병합 커밋 `b3b45156cfb7265e99e46c4f3b86f9023144ad18`부터 Rust/Tauri 통합 코드가 들어 있다.
- 병합 직전의 구 `main`은 `backup/main-before-rust-integration-20261116` (`30a19cd2da7533dd2ed36b807593309bde70a7eb`)에 보존한다. 복구 판단 없이 덮어쓰거나 지우지 않는다.
- `integration/final-rust-migration-20261116`은 이전 통합 검증 기준을 추적하기 위해 보존하지만 **새 작업의 기반으로 사용하지 않는다**.
- `main` 통합 완료, 전체 Rust 업무 소유권 이전 완료, 반도 현장 배포 승인 및 기존 운영 데이터 이관 승인은 **서로 다른 상태**다.

## 새 작업 방식

1. GitHub Desktop에서 `Fetch origin` 후 `main`으로 전환하고 `Pull origin`으로 최신 상태를 가져온다.
2. **매번 최신 `main`에서** `fix/<문제>` 또는 `feat/<기능>`의 짧은 작업 브랜치를 만든다. 여러 병렬 세션은 소유 파일과 작업 범위를 서로 겹치지 않게 분리한다.
3. 해당 브랜치에서 수정·타입 검사·업무 동등성·회귀 테스트를 완료하고 `main`을 대상으로 PR 하나를 만든다.
4. `main` 대상 PR에서 `.github/workflows/migration-output.yml`의 **Rust/Windows 15개 선행 작업 + 최종 게이트**가 모두 성공해야 병합한다. 별도 `verify-tauri.yml` 회귀 검사도 실패를 방치하지 않는다.
5. PR을 `main`에 병합한 후 `main`에서도 동일한 통합 CI를 다시 실행한다. 검증된 병합 SHA를 업무 기록에 남긴다.
6. 완료된 작업 브랜치는 원격 병합·데이터 보존을 확인한 뒤 삭제할 수 있다. 유일한 변경점이 남은 **분기된 브랜치는 삭제하지 않는다**. PR 종료는 브랜치 삭제와 다르다.

## 작업 종료 기준

- Rust 이전 작업 완료: 실제 운영 UI의 업무 판단이 Rust를 호출하고, 원래 TS 테스트 오라클과 동등하며, 업무 데이터 보존과 Windows 네이티브 동작을 확인한 상태.
- UI 안정화 완료: 실데이터형 주문·상품·배송, 다양한 화면 크기와 배율, 카카오톡 연동 등 실제 UI 기준을 충족한 상태.
- 현장 배포 완료: 배포용 EXE, 원래 DB 백업·복원·설치, 작업자 인수 검증을 모두 통과한 상태.
- `main`의 CI 성공만으로 위 3가지를 한꺼번에 완료 처리하지 않는다.

## 금지사항

- `main` 또는 오래된 브랜치에 `force push`하여 기록을 덮어쓰지 않는다.
- 내용이 다른 과거 작업 브랜치를 확인 없이 일괄 삭제하지 않는다.
- 타입스크립트 화면 코드 및 ExcelJS 파일 생성까지 무조건 Rust로 제거하려 하지 않는다.
- 이미 병합한 이전 PR을 다시 머지하거나 무검증 병렬 세션 변경을 한 PR에 섞지 않는다.
