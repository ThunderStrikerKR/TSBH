# 157차 F01~F08 무결성 보완
감사 docs/validation-coverage-audit-157.md 기준. 2431d990에서 F01~F04/F06 우선 반영, 후속 F05/F07/F08.
- F01 기존 상품의 variant ID 집합 변경 및 신규 중복/빈 ID 거부. 일반 편집과 판매단위 마이그레이션 분리.
- F02 alias_problem과 같은 조건에서 충돌 대상 ID 및 관련 근거를 수집, 공통 비교기 사용. 기존 전용 명령 오류 문구 중복 제거 및 순서 유지. 이름/모델/색상 충돌 비교는 기존 의미 유지.
- F03 기존 매핑의 key/value 모두 보존. 별도 복구/마이그레이션 계약 필요.
- F04 현재 기준이 그대로면 신규 이력 불허. 기존 운임 변경은 정확히 1개 이전 기준과 신규 버전 요구, 현재 기준 제거 차단. 신규 기준 초기화의 null 이전값 1개는 기존 명령 호환. 신규 그룹/새 이력 키에도 검사. 복수 기준 변경의 일괄 트랜잭션은 별도 증명 필요.
- F05 회신 기록 변경 시 기존 validate_factory_scope 및 ensure_customer_payment_unchanged 직접 재사용. 전용 회신 트랜잭션의 보호 범위 유지, 다른 업무/리비전 변경을 결합한 후보는 허용하지 않음. 운영 회신 경로의 기존 검증 유지.
- F06 정확한 기존 product_key를 재사용, 신규/복원 상품의 삭제 기록 키 충돌 거부, 새 삭제에 키 보존 요구. 유사 상품명이나 다른 variant ID의 동일 실물 상품 판정까지 보장하지 않음.
- F07 기존 주문 검증에 전역 주문/수취인/품목 ID 검사 및 신규 감사 기록 검사 연결. SQL 기록은 생성하지 않음.
- F08 기존 업무 상태 null/누락 전체 삭제와 비객체 변경 거부. 기존 공통 Rust validator에 적용; 초기 workflow 없는 상태는 허용. 모든 하위 컬렉션 규격 정리는 별도.
- 신규 단위 테스트 8개 작성, validation_transitions 기존 누락 CI 그룹 추가. 실제 compile/CI/SQLite 미실시. 중앙 실행기 저장 연결 없음. 정상 native 명령의 결과와 비교 및 O01~O08 해결 전 운영 연결 금지. 기존 등록부의 호출 범위 및 전체 레거시 정책 보완은 별도.
