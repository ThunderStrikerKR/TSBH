# 공장 회신 Excel 반려·보류 판정표 (32차)

## 원칙

공장 회신 파일을 읽을 수 있는지와 배송 건을 자동으로 적용할 수 있는지는 별개다.
파일 전체 반려는 원본이 손상되었거나 필수 추출 위치를 전혀 찾을 수 없는 경우에 한정한다.
정상 행은 자동 반영하고, 신뢰할 수 없는 개별 행은 직원 확인으로 보류한다.
자동 반영은 Rust의 배송 건 유일 매칭·기존 운송장 및 운임 충돌 검사를 반드시 통과해야 한다.
반려/보류 모두 기존 SQLite 배송 데이터를 변경하지 않는다.

## 파일 전체 반려

- .xlsx가 아니거나 파일이 0바이트, 10MiB 초과, 읽기 불가능하거나 손상됨
- 첫 번째 워크시트가 없거나 데이터가 1,000행을 초과함
- 처리할 배송정보가 한 행도 없거나, Q열 송장번호가 전체 행에서 빠짐
- 동일 파일 해시가 이미 등록된 경우 재등록 금지 (중복으로 판정, 원본 불변)
- 미리보기 이후 DB revision 변경·원본 파일 해시 불일치·저장 전 재검증 실패

## 행 단위 보류 (다른 정상 행은 처리)

- 수취인 이름(A), 주소(C), 전화(D/E 중 하나) 누락
- 실제 운임(G) 미입력·음수·비정수·정밀도 오류
- 송장번호(Q)가 8~30자리 숫자가 아님 (하이픈·공백 제거 후 검사)
- Q열 숫자형 셀 값이 부정확하거나 15자리 초과, 앞자리 0 표시 형식과 저장 값이 충돌할 수 있음
- 업무 관련 A/C/D/E/G/Q 셀의 수식, 병합 셀 또는 해석 불가능한 객체 값
- 회신 파일 내 유효한 송장번호 중복 또는 동일 배송 건 중복 행
- 공장에서 Excel로 내보낸(EXPORTED) 배송 건이 아니라거나, 이름+주소+전화 중 하나라도 매칭되지 않음
- 일치 후보가 없거나 여러 배송 건에 중복 일치함
- 운송장번호가 다른 배송 건에 이미 연결됨
- 이미 저장된 운송장번호 또는 실제 출고 운임과 충돌 (직원 확인 후 한 행 정정 가능)

## 정상 자동 반영

- 보관 가능한 원본 파일, 필수 정보 및 유효한 송장번호
- Q열이 텍스트인지 숫자형인지 자체는 반려 이유가 아님
- 숫자형은 8~15자리의 정확한 안전 정수이고 앞자리 0 손실 의심 서식이 없어야 함
- 유일한 EXPORTED 공장 배송 건과 수취인 이름·주소 및 최소 1개 연락처 일치
- 송장번호/실제 운임의 중복·충돌 없음
- 이미 반영한 동일 송장번호·운임 재회신은 감사 가능한 중복 회신으로 보존, 중복 수정 없음
- 실제 출고 운임과 공장 송장만 갱신하고 상품 가격·고객 청구 운임·입금·원본 주문은 보존

## 더 이상 전체 반려 사유가 아닌 것

- J열에 메모나 다른 데이터가 기록됨
- Q열 뒤 R열부터 다른 정보가 기록됨
- 어떤 한 행만 잘못된 송장번호·수식·병합 셀 등을 포함함
- 앞자리 0/정밀도 위험이 없는 일반적인 숫자형 송장번호

## UI

- 우측 상단은 벨 아이콘과 '알림' 버튼으로 표시한다.
- 잠깐 떴다가 사라지는 블록형 토스트는 표시하지 않는다.
- 알림 목록에서 수신 파일·시각·처리 결과·보류 행·이유를 상세 조회한다.
- 정상 반영된 이력과 보류된 이력은 기존 공장 회신 이력 및 SQLite 감사 기록과 연결된다.
- 미등록/반려 파일의 알림은 현재 실행 중 알림 센터에서 확인할 수 있으며 DB는 변경하지 않는다.
