# BANDO HUB 관리 화면 공통 UI 수칙 (2026-11-20 개편)

> **최신 공동 마스터 정식 계약:** [egui 관리 UI SSOT](egui-management-ui-ssot.md). 이 문서는 이식 및 화면별 상세 체크리스트이며, 61차 이후에는 SSOT가 지정한 Rust 토큰·공통 함수·명시적 예외를 우선한다.

> **현행 Rust/egui 관리 화면 구현의 유일한 상세 기준:** [2026-11-20 운임 관리 승인 레퍼런스](egui-management-ui-reference.md)
>
> 기존 React/CSS 관리 화면 가이드는 과거 구현·기능 비교에만 사용한다. egui 규격에 예전 React 40px 버튼이나 13pt 표 헤더를 자동 이식하지 않는다. 이 문서는 **적용 시점의 체크리스트**이며, 다른 탭에 실제 UI 변경을 끝냈다는 뜻은 아니다.

## 1. 적용 대상·우선순위

- 대상: 주문 내역 / 엑셀 관리 / 일일 결산 / 상품 관리(모델군·별칭·브랜드·카테고리 포함) / 운임 관리 / 거래처 관리 / 설정의 관리형 탭과 목록.
- 예외: 접수는 공통 메뉴·서체·컨트롤 역할을 사용하되, 카카오톡 도킹과 원문·수취인·처리 중 주문의 자체 구조·비율을 유지한다. 모달·팝업은 별도 계약 우선.
- 최신 명시적 사용자 지시 → [egui 승인 관리 UI 기준](egui-management-ui-reference.md) → 화면별 기존 기능·특수 UI 계약 → 과거 React 원본/타입스크립트/CSS 수치 순서로 읽는다.
- 목표는 화면이 서로 **같은 역할·정보 밀도·타이포그래피·여백·정렬·스크롤 체계**를 공유하는 것. 표 열 수·업무 필드·저장 정책까지 똑같이 만드는 것은 아니다.

## 2. 관리 화면 공통 구성

1. **18pt/44pt 전역 메뉴** (메인 헤더 62pt) → **20pt 화면 제목** → **16pt/38pt 하위 탭**. 상위 활성색은 파란색, 하위 활성색은 중립 회색.
2. 필요한 화면에서만 독립 KPI 카드 사용: **28pt 숫자 위 / 13pt 보조 라벨 아래**, 카드별 분리. 운임 기준 228×80pt; 다른 화면은 실제 통계와 공간에 맞게 확장한다.
3. 섹션: **제목·도움말 → 검색/필터 왼쪽 · 선택/일괄 작업 오른쪽 → 구분선 → 헤더 고정 표 → 행 스크롤**. 검색창이 스스로 의미를 설명하면 중복 '검색' 레이블을 추가하지 않는다.
4. 역할별 공통 공간 토큰 4/8/12/16/24pt, 단일 섹션 외곽 테두리, 표 내부 1pt 구분선 및 은은한 교차 행 배경 사용.
5. 버튼 크기·글씨·색을 화면마다 임의로 변경하지 않는다. 반복되는 기본 설정 버튼은 중요도를 낮춘 보조 역할로 그리되 기존 클릭 면적과 기능은 유지한다.

### 61차 확정 — 도구줄 오른쪽 끝 좌표 계약 (CONFLICT-001 / C안, 2026-11-21)

- 승인 마스터는 **운임 관리 → 배송 그룹 편성**과 **주문 내역**이다. 두 화면의 주 목록 카드 도구줄 오른쪽 끝은 **카드 내부 오른쪽 경계**에 맞춘다.
- 도구줄은 표 스크롤바 레일을 차감하지 않는다. 검색·날짜 필터·일괄 적용 작업처럼 역할이 달라도 이 오른쪽 기준선은 동일하다.
- 위치는 `components::management_toolbar_trailing_rect(toolbar_rect,slot_width,top_offset,height)`에서 한 번 계산한다. 일반 도구줄 높이는 36pt, 필터·선택 버튼 높이는 34pt. 주문 내역의 좁은 창 줄바꿈은 허용하되 각 줄의 오른쪽 끝은 같은 기준을 지킨다.
- **표의 열·헤더·본문은 별도 계약:** 헤더와 행은 스크롤바 레일(기본 10pt)을 제외한 데이터 너비를 공유한다. 도구줄 버튼 끝과 마지막 데이터 열이 10pt 다르게 끝나는 것은 오류가 아니다.
- 런타임 좌표 자동 수집·Windows 실화면 검증은 별도 단계이며, 이번 반영은 공통 사각형 계산과 디버그 불변식 및 집중된 기하 테스트 코드까지다. 업무별 선택/저장 흐름은 변경하지 않는다.
- **CONFLICT-002 확정(2026-11-21):** 두 마스터의 열 너비는 현재 Rust/egui 소스값을 유지한다. 이 문서에 남아 있던 이전 수치는 현행 코드 기준으로 정정하며, 화면에 대한 열 너비 변경은 하지 않는다. 승인된 수치 및 화면별 예외는 `docs/egui-dual-master-ui-contract-draft.md`를 따른다.

### 59차 확정 — 큰 박스 **외곽** 위치와 크기 표준화 (2026-11-20)

- 사용자가 가리키는 **표의 위치**는 표 헤더/행의 좌표나 내부 패딩이 아니라, **'운임 관리 → 배송 그룹 편성'에서 '상품별 배송 그룹 지정'을 감싸는 가장 바깥 큰 박스의 외곽 위치**다. 이전에 내부 여백만 맞추는 것으로 해석한 지침은 이 확정 계약으로 정정한다.
- **주요 박스의 위쪽 테두리·왼쪽 시작·오른쪽 끝**을 배송 그룹 편성 화면과 통일한다. 타이틀/탭/KPI가 없는 메뉴는 **빈 공간을 허용**해 박스가 위로 붙지 않도록 한다. 화면마다 불필요한 하위 탭·가짜 KPI 카드·빈 상태 메시지를 넣지 않는다.
- 기준 세로 위치는 관리 화면 자체의 콘텐츠 시작점으로부터 계산한다. 공통 `theme::management_primary_card_top_offset()`과 `components::align_management_primary_card()`가 기준을 소유하며, **최종 승인된 배송 그룹 편성 화면의 상단 10pt 추가분(기존 작업영역 6pt와 합쳐 16pt), 28pt 제목 행, 8pt 제목→탭, 38pt 탭, 12pt 탭→통계, 80pt 통계 카드, 16pt 통계→박스, egui 8pt 기본 행간격×3**을 반영한다. 통계 카드 4개가 한 줄이면 박스 외곽 기준 높이는 페이지 원점에서 **216pt**다. 좁은 화면에서 통계 카드가 여러 줄이면 예약 높이도 늘린다. 캡처의 고정 화면 좌표를 화면별로 복제하지 않는다.
- **단일 목록형 큰 박스는 가능한 한 화면 아래쪽 작업영역 끝까지 확장**한다. `components::management_primary_card_min_inner_height()` / `fill_management_primary_card()`를 사용한다. 데이터가 많으면 기존 내부 스크롤·한 줄 표·헤더 고정은 그대로 유지한다. 카드가 여러 개 이어지는 정산·설정·운임 이력 화면에서는 첫 박스 시작선만 공유하고 각 박스의 독립 높이/스크롤은 유지한다.
- 거래처 자동 메시지는 두 개의 **병렬 편집 박스**를 같은 기준 높이에서 시작하며 가능한 한 같은 높이로 확장한다. 상품 관리의 모델군·카테고리·별칭·브랜드도 각 화면의 최상위 박스 외곽을 맞춘다.
- **일일 결산 날짜 선택은 독립 상단 박스가 아니라 첫 번째 '일일 결산 조회' 큰 박스 내부에 둔다.** 주문 내역과 동일한 이전/다음 날짜·날짜 입력·'달력' 버튼을 사용한다. KPI는 큰 박스 바깥에 유지한다. 상품 등록/Excel 확장 패널이나 오류 알림 등 꼭 필요한 내용이 기준선보다 길어질 때에는 **겹침을 강제로 만들지 않고 자연스럽게 아래로 확장**한다.
- 내부의 표 열 폭, 검색/필터 입력, 액션, 서체, 저장 동작, 데이터 모델은 이번 위치 통일의 대상이 아니다. **59차 최초 오해로 변경했던 목록 내부 패딩·툴바 좌우 여백·상품/설정 탭 바로 아래 간격은 기존값으로 복구했다.** `section_frame()`의 16pt와 `management_list_frame()`의 기존 1pt 외곽 인셋은 그대로 다를 수 있다. 같은 위치에 맞추는 대상은 이들 **외곽 박스 테두리**이지 내부 콘텐츠가 아니다.
- 코드 변경과 정적 앵커 검증은 실제 Windows 빌드·실화면·다중 DPI·스크롤/포커스 검증과 **구별해 보고**한다.

- **박스 외곽 미세 오차 교정(2026-11-21):** 제목 여백·세로 간격 수정 이전의 공통 오프셋 214pt와 현재 승인 레퍼런스의 216pt가 달랐던 원인을 수정했다. 모든 관리 화면의 첫 큰 박스는 공통 함수의 같은 목표 Y에 맞춘다. 단, 상단에 실제 업무 내용이 더 길면 기존 합의대로 강제 겹침 없이 자연스럽게 아래로 연장한다. 박스 내부 패딩과 표 행 높이는 이 교정 대상이 아니다.

### 59차 추가 확정 — 관리 화면 상단 제목·탭·통계 정렬 (2026-11-21)

- 사용자 승인 레퍼런스: **운임 관리 → 배송 그룹 편성**의 최종 상단 배치. **제목 좌측 16pt, 제목 상단 최종 16pt**. 상단 16pt는 기존 작업 영역 외곽 6pt를 **포함**하며 추가로 16pt를 쌓지 않는다.
- 제목·옆 도움말·우측 기준 정보·존재하는 하위 탭·통계 카드·목록 바깥 제목/액션은 공통 **좌측 16pt** 기준선을 사용한다. 큰 박스 **외곽**은 59차 전 화면에서 합의한 작업영역 시작/끝 좌표를 계속 유지한다. 상단 콘텐츠를 정렬하려고 목록 박스 전체를 16pt 안으로 옮기지 않는다.
- 있는 요소의 세로 리듬: **제목→하위 탭 8pt, 하위 탭→KPI 12pt, KPI→주요 큰 박스 16pt**. 이는 해당 요소가 실제 존재할 때의 간격이며, 없는 요소의 공간을 가짜 탭·KPI·설명으로 채우지 않는다.
- **하위 탭이나 KPI가 없는 화면**: 진짜 제목과 기존 상단 도구를 정상적으로 배치한 다음, 남는 공간은 **마지막 실제 상단 요소와 큰 박스 사이**에 둔다. 첫 큰 박스의 외곽 위쪽 기준은 `components::align_management_primary_card()`가 유지한다. 추가 내용이 기준선보다 길어지면 강제로 겹치지 않고 자연스럽게 아래로 확장한다.
- 화면별 적용: 주문 내역은 제목만, 엑셀·상품·거래처·설정은 제목+탭, 일일 결산은 제목+실제 KPI(날짜 선택은 아래 큰 박스 내부), 거래처 자동 메시지는 하위 편집 탭까지 정렬한다. 상품 목록의 기존 제목/액션도 공통 16pt 정렬을 따르되 상세 업무 패널의 구성은 유지한다.
- 소스 소유자: `components::management_page_title_top_gap()`이 최종 상단 16pt를, `components::management_top_content()`가 상단 콘텐츠 가로 16pt를 소유한다. **접수·카카오톡 도킹·워크스페이스 외곽 6pt·59차 큰 박스 위치/크기는 불변**이다.
- 이번 적용은 Rust 소스·문서 기준이다. CI·Rust 빌드·Windows 실화면·다중 DPI 시각 검수는 각자 별개로 기록한다.

### 일일 결산 날짜 선택 통합 (2026-11-21)

- 별도 상단 날짜선택 박스를 제거하고, **첫 결산 표의 바깥 큰 박스 내부에서 제목 다음 줄**에 `결산 날짜 · ‹ · YYYY-MM-DD · 달력 · ›`를 표시한다. 날짜의 유효성 확인, 선택 날짜에 대한 Rust 조회, 조회 중/오류 상태 메시지도 해당 박스에 속한다.
- 주문 내역에서 승인한 7열 달력 팝업(연/월 이동, 선택 날짜 강조)을 `components::date_calendar()`로 공통화한다. 각 메뉴는 별도 ID와 날짜 상태를 유지하며 주문 내역의 기존 검색/접수 날짜 정책을 수정하지 않는다.
- **통계 카드 4개**, 결산 주문/청구 표, 실제 입금 표, 검토 사항은 유지한다. 자료가 없거나 로딩 중이어도 첫 박스 날짜 선택은 표시하며, 날짜를 변경하면 이전 데이터를 그대로 보여주지 않고 해당 날짜의 조회를 다시 시작한다.
- 첫 큰 박스의 외곽 위치는 59차 기준대로 유지한다. 두 번째 입금 표와 스크롤 구획을 불필요하게 합치지 않는다.

### 주문 내역: 배송 그룹 편성 내부 레이아웃 기준 적용 (2026-11-21)

- **외곽 큰 박스 위치와 크기는 59차 기준 그대로** 유지한다. 두 단일 목록 마스터(배송그룹 편성·주문내역)는 `management_master_table_frame()`을 사용해 **상하좌우 16pt**를 적용한다. 표 데이터는 하단 16pt 위에서 종료하고, 스크롤바 레일만 해당 여백의 중앙까지 연장해 카드 하단 8pt 앞에서 종료한다. 본문 뷰포트를 연장하지 않는다. 일반 섹션 카드는 기존 `section_frame()` 상하좌우 16pt를 유지한다. 다른 관리 탭의 패딩은 이 수정 범위에 포함하지 않는다.
- **페이지 제목:** 운임 관리와 동일한 `page_heading`(20pt), 좌측·상단 최종 16pt. 하위 탭과 KPI가 없으므로 큰 박스 위의 빈 공간은 유지한다.
- **목록 내부:** 배송 그룹 편성의 실제 배치와 일치하도록 **36pt 고정 검색/기간 도구줄 → 총 21pt 전환(도구줄 아래 16pt/구분선 1pt/아래 4pt) → 36pt 고정 헤더(하단 2pt `TABLE_HEADER_OUTLINE`) → 42pt 고정 데이터 행**으로 구성한다. CONFLICT-005에 따라 두 마스터 모두 `management_sticky_table_header`의 21pt를 사용하며, 구분선/헤더/행 사이에 별도 자동 간격을 추가하지 않는다.
- **가로:** 검색창은 큰 박스 안쪽 좌측 16pt 시작선, 날짜 기준/시작일/종료일/전체 날짜 도구는 **스크롤바 여백을 따로 빼지 않고 큰 박스 안쪽 오른쪽 16pt 경계**에 맞춘다. `전체 날짜` 버튼의 마지막 오른쪽 끝을 기준으로 내부 LTR 레이아웃의 `main alignment=Max`를 사용한다. 조회 도구줄은 스크롤바가 없으므로 표에서만 사용하는 10pt 레일을 여기서 제외하지 않는다. 좁은 화면에서는 기간 도구만 아래로 줄바꿈하고 줄마다 LTR + 우측 정렬한다. **표 헤더·데이터 행은 기존처럼 오른쪽 10pt 스크롤바 레일을 유지**하고 큰 박스 외곽 위치는 바꾸지 않는다.
- **표:** 헤더와 본문은 같은 열 좌표·가로 스크롤 오프셋을 공유한다. 문자형 열의 왼쪽 시작은 셀 내 6pt, 금액은 오른쪽 8pt, 관리 상태/처리는 가운데 정렬한다. 본문 강조·보조 문자 크기는 기존 `typography` 역할을 유지한다.
- **스크롤:** 배송 그룹 편성과 동일한 `management_scroll_style()`의 **10pt 실선 레일·최소 핸들 길이 44pt·스크롤바에 별도 양옆 0pt 여백**을 사용한다. `ScrollArea::both().scroll_bar_rect(...)`는 실제 표 본문 맨 위에 **0pt 간격으로 연결**하고 스크롤바에만 하단 11pt 연장(공통 트랙 하단 3pt 보정 포함)을 적용해 카드 외곽선에서 8pt 앞에 끝나도록 예약하며, `VisibleWhenNeeded`로 행이 넘칠 때만 표시한다. 표 헤더 배경은 전체 너비로 그리되 **오른쪽 10pt 레일을 제외한 `header_content_rect`에만 글자·열 구분선·정렬 클릭을 허용**한다. 표 헤더와 본문은 같은 가로 스크롤 원점 및 열 폭을 사용한다. 조회 결과가 없으면 표 헤더 아래 **데이터 표시 영역의 가로·세로 중앙**에 안내만 표시하고 레일을 강제로 띄우지 않는다.

### 주문 내역: 고정 정보 열 최소화·상품 중심 상세 보기 (2026-11-21)

### 주문 내역 표: 단일행 배송 요약·직원 입금 확인 (2026-11-21)

- **배송 건 / 상품**: 최신 목록 기준은 바로 위의 **모든 상품명 × 수량을 한 줄에 나열**하는 방식이다. 과거 배송 건수·품목 수·최대 2개 상품 미리보기를 앞에 붙이던 배치는 사용하지 않는다. 펼친 주문의 상세행에서 수취인·상품·실제 운임 등을 확인한다.
- **청구 합계 바로 오른쪽**에 `입금 확인` 열을 신설한다(7열 순서: 접수일 / 거래처 / 배송 건·상품 / 관리 상태 / 청구 합계 / 입금 확인 / 처리). 여기는 *실제 계좌 입금일 `payments[].paidAt`*이 아니라 **직원 승인 기록 `workflow.confirmations[].confirmedAt`의 서울 날짜**를 표시한다. 입금일 기준 기간검색과 의미를 혼동하지 않는다.

### 주문 내역: 조회 기준 및 두 날짜 달력으로 기간 검색 (2026-11-21)

- 관리형 큰 박스의 상단 검색 도구줄에서 **거래처 / 주문 내용 검색은 왼쪽**, **조회 기준·기간 검색은 오른쪽**에 둔다. 좁은 작업 영역에서는 기간 검색만 아래 줄로 내려가며, 좌우 큰 박스 위치나 표 너비는 바꾸지 않는다.
- 조회 기준은 `접수일 기준` / `입금일 기준`이며, **148pt × 34pt 드롭다운**에서 선택 문구는 왼쪽, 아래 화살표는 분리된 우측 30pt 영역에 배치한다(양쪽은 1pt 구분선). 일반 단추에 `▾` 문자만 붙이는 방식은 금지한다. 메뉴는 독립 팝업으로 열어 도구줄에서 클리핑되지 않도록 한다. `시작일`·`종료일`의 표제 텍스트는 생략하고 날짜마다 **`‹ 날짜 입력 › 📅`**을 한 묶음으로 제공한다. 날짜 입력은 `YYYY-MM-DD`에 맞는 **106pt 폭, 텍스트 가로 중앙 정렬**을 사용한다. 각 날짜는 **36pt 높이의 하나의 바깥 테두리** 안에 `‹ | 날짜 입력 | › | 📅`의 네 구역을 넣고, 구역 사이에는 공간 대신 **1pt 세로 구분선**을 사용한다. 두 날짜 묶음 및 조회 기준·전체 날짜 사이의 외부 간격은 기존 8pt를 유지하고 오른쪽 정렬한다. 날짜 검색 영역은 종전의 940pt 예약폭을 사용하지 않고 **704pt 기준으로 최적화**한다. `‹`·`›`는 **인접한 날짜만 하루씩 변경**하고 기본값은 오늘~오늘, `전체 날짜`는 두 날짜만 비운다.
- **날짜 배치 역전·누락 재발 방지(2026-11-21):** 오른쪽 정렬은 **날짜 묶음 전체를 놓을 사각형의 X 좌표 계산**에만 사용한다. 묶음 안의 컨트롤은 단일 `UiBuilder.layout(left_to_right(Align::Center))` 하위 UI 안에서 **조회 기준 → 시작일 `‹ | YYYY-MM-DD | › | 📅` → `~` → 종료일 `‹ | YYYY-MM-DD | › | 📅` → 전체 날짜** 순으로 한 번만 배치한다. 두 줄 배치도 줄별로 오른쪽 X 좌표를 계산한 뒤 **각 줄 자체는 LTR**로 그린다. `Ui::put`으로 겹쳐 삽입하거나 날짜 묶음 안에 RTL 레이아웃을 중첩하지 않는다. 기존 106pt 날짜 입력과 36pt 그룹 높이, 구분선, 오른쪽 기준선은 유지한다.
- **큰 박스 안 수직 리듬:** 배송 그룹 편성과 동일하게 페이지의 주 박스 안에서 **36pt 도구줄을 먼저 한 번 예약 → 21pt 공통 전환(16pt/선 1pt/4pt) → 36pt 표 헤더 → 42pt 데이터 행**으로 구성한다. 도구줄 전체를 `section.scope`로 감싸서 기본 `item_spacing.y`가 헤더 앞에 추가되지 않도록 한다. 로딩·유효성 오류·조회 실패·빈 결과 안내는 도구줄과 헤더 **사이에 새 줄로 넣지 않고**, 헤더 아래 데이터 영역 중앙에 상태별 색상으로 표시한다. 큰 박스 외곽과 다른 관리 화면은 수정하지 않는다.
- **날짜 컨트롤 높이 검수 교정(2026-11-21):** `Frame::show` 안에 `with_layout` 또는 `horizontal`을 중첩해 34pt 높이 위젯을 넣으면 예약된 36pt 위로 2~4pt 추가 높이가 생길 수 있다. 주문 내역 날짜 그룹은 외부에서 **36pt 사각형을 한 번만 예약**, 내부 사각형은 **1pt inset을 뺀 34pt**로 고정하고 `UiBuilder.max_rect`와 **LTR** 순차 배치로 네 요소를 넣는다. 별도 `Frame::show` 중첩이나 `Ui::put` 재배치 금지. 검색창·두 날짜 그룹의 상하 중앙이 일치해야 하며, 상태 메시지와 빈 결과가 헤더 앞의 21pt 전환을 늘려서는 안 된다.
- 시작일·종료일을 **양끝 포함**으로 검색한다. 한쪽이 비어 있으면 열린 구간, 둘 다 비어 있으면 날짜 범위 제한이 없다. 시작일이 종료일보다 늦거나 날짜가 유효하지 않으면 검색을 실행하지 않고 안내를 표시한다.
- `접수일 기준`은 기존 Rust 주문 내역 규칙의 `confirmedAt`(없으면 `createdAt`)을 서울 날짜로 해석한다. `입금일 기준`은 Rust `workflow.payments[].paidAt`을 서울 날짜로 해석하고, **양수 입금 배분(`allocations[].shipmentId` → 해당 주문의 현재 배송 건)** 연결이 입증된 주문만 검색한다. 입금 승인 여부·`paid` 플래그·배분되지 않은 계좌 입금만으로 특정 주문을 매칭하지 않는다.
- 기존 `list_order_history` 단일 접수일 계약과 일일 결산은 그대로 둔다. 신규 기간검색은 기존 `list_order_history_view`의 명시적 선택 인자로만 실행한다. Excel 이력에서 주문으로 이동하는 기능은 해당 주문의 **접수일 하루·접수일 기준**으로 이동한다.

- **헤더와 본문 14pt, 헤더 36pt, 기본 한 줄 행 42pt.** 유효한 업무 예외는 해당 테이블에 기록한다.
- **체크박스/작업/드롭다운 가운데**, **상품명·카테고리·색상/옵션·거래처명 왼쪽**, **금액·수량 오른쪽**. 헤더도 같은 기준으로 정렬한다.
- 정렬 가능한 헤더는 제목 옆 정렬 아이콘을 표시하며 **기본↕ → 오름▲ → 내림▼ → 기본**. 필터 결과 전체를 정렬한 후 가상 렌더링한다.
- 무한 하위 분류가 가능한 카테고리는 **앞 경로를 생략하고 마지막 분류를 남긴다**. 상위 경로는 흐리게, 마지막 분류는 14pt Bold로 더 선명하게 표시하고 전체 원문은 보존한다.
- 색상/옵션·정렬 아이콘·버튼·카테고리의 실제 너비를 먼저 확보한다. 남는 폭은 의미별로 배분하며 기존 화면의 6열/942pt 배열을 그대로 복사하지 않는다.
- 체크박스·드롭다운·조건부 버튼 유무와 관계없이 같은 표의 행 높이와 기준선이 안정적이어야 한다. 첫 행만 높거나 아래 행이 압축되면 실패다.
- 표 내부 고정 헤더·solid 스크롤바(레퍼런스 10pt, 최소 핸들 44pt)·스크롤바 공간 예약. 데이터/작업 버튼 위로 스크롤바가 겹치거나 불필요한 가로 스크롤이 생기면 실패다.

## 4. 공통 코드 소유자

| 책임 | 현행 egui 코드 |
| --- | --- |
| 글꼴/역할 | `egui-app/src/typography.rs` |
| 색상·여백·버튼·표·KPI·스크롤 토큰 | `egui-app/src/theme.rs` |
| 하위 탭·공통 컨트롤·가상 목록 | `egui-app/src/components.rs` |
| 페이지별 실제 열·필터·정렬 키·업무 호출 | 각각의 관리 화면 모듈 |

- React 이전의 `src/styles/management-layout.css`, `shipping.css`, `PageHeading`, `ManagementSearch` 등은 **React 비교 참조**로 남긴다. egui의 시각적 단일 진실원으로 사용하지 않는다.
- 개별 화면에 새 RGB·고정 글씨·임의 패딩을 덧붙이지 말고 소유 토큰을 정리한다.
- 실제 저장·업무 판단은 Rust의 기존 API/DB 소유권 그대로 유지한다. UI 통일을 이유로 새로운 저장 버튼·임시값·팝업·동작을 만들지 않는다.

## 5. 적용 순서 및 판정

1. 대상 탭의 기존 기능, 버튼, 상태, 데이터 최대 길이, 레이아웃을 목록화한다.
2. 공통 역할에 매핑하되 특수 화면·폼·업무 조건은 예외로 기록한다.
3. 제목/하위탭 → 통계(있으면) → 섹션/툴바 → 표/리스트 → 팝업/오류/빈 상태 순서로 단계별 수정한다.
4. 상품·거래처 **1개당 1줄**, 헤더-셀 좌표, 체크박스·버튼 중심, 고정 스크롤바/클리핑, 여러 창 폭과 DPI를 확인한다.
5. 클릭·검색·정렬·필터·편집·저장·이탈·오류 복구가 이전과 동일하게 동작하는지 검증한다.
6. **소스 반영·CI·Windows 실제 캡처·실제 동작**을 구분해서 보고한다. 어느 하나만 통과하면 전체 완료로 보고하지 않는다.

**적용 상태(문서 개편 시점):** 운임 관리 편성 화면을 레퍼런스로 **확정**, 다른 하위 탭은 **순차 적용 예정/미검수**. 과거 React 관리 화면 단계별 작업 목록은 git 이력에서 확인하며 현재 egui 완료 목록으로 승계하지 않는다.
