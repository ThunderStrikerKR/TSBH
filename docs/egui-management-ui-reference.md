# BANDO HUB — egui 관리 화면 공통 UI 기준 (2026-11-20 확정)

> **기준 화면:** 사용자가 2026-11-20 최종 승인한 **운임 관리 → 배송 그룹 편성** 화면(상단 메뉴·하위 탭·4개 분리 통계 카드·상품 목록이 함께 보이는 캡처).
>
> **상태:** **새로운 관리 화면 구현·수정의 디자인 기준으로 확정.** 이 문서가 생성되었다고 다른 탭에 일괄 적용된 것은 아니다. 기존 화면의 실제 적용·Windows 검수는 화면마다 별도로 기록한다.
>
> **우선순위:** 최신 명시적 사용자 지시 → 이 문서(egui 공통 관리 UI 역할) → [egui UI 재구축 계약](egui-ui-design-contract.md)의 나머지 기능·화면별 예외 → React/CSS의 과거 이식값. Rust 업무·저장 정책은 시각적 규격 변경으로 덮어쓰지 않는다.

## 1. 레퍼런스에서 확정한 방향

1. **구조적 위계:** 전역 내비게이션 → 화면 제목 → 하위 탭 → 필요할 때만 요약 카드 → 실무 섹션(제목/도구줄/표) 순서. 상위 메뉴를 크게 하고 하위 탭을 지나치게 줄이지 않는다. 둘의 활성 배경색을 구분한다.
2. **분리된 정보 블록:** 요약 수치가 여러 개일 때는 각각 **별도 카드**로 유지하고, 한 개의 통계 막대로 합치지 않는다. 숫자를 위에 크게, 항목명은 아래에 작게 표시한다. 카드 개수·값은 업무에 따라 달라진다.
3. **한 줄 데이터와 동일한 좌표:** 목록은 기본적으로 **항목 1건=1행**. 헤더-본문의 열 경계와 시작선, 체크박스/버튼의 세로 중심, 구분선, 스크롤 위치가 같은 좌표계에 있어야 한다.
4. **업무 정보 우선:** 사용자 식별 데이터(상품명·거래처명 등)를 가장 읽기 쉽게 두고, 상태·반복 버튼은 보조 위계로 내린다. 의미가 중복되는 열·상태 안내·저장 버튼을 임의로 추가하지 않는다.
5. **읽을 수 있는 스크롤:** 스크롤바는 호버하지 않아도 표시되는 **solid/nonfloating** 계열을 사용한다. 데이터·버튼을 덮거나 첫 행을 늘리거나 아래 행을 압축해서는 안 된다.
6. **실제 실행 화면이 검수 기준:** 소스·문서·CI 통과를 Windows 실화면 합격으로 간주하지 않는다.

## 2. 공통 역할별 크기와 텍스트

단위는 egui의 논리 point(pt)이며 실제 Windows DPI/배율 검수가 별도로 필요하다.

| UI 역할 | 글씨 | 높이/구조 | 기본 정렬·강조 | 코드 소유권 |
| --- | --- | --- | --- | --- |
| 상단 전역 내비게이션 | **18pt** | 버튼 **44pt**, 전역 바 **62pt** | 선택 파란 배경, 나머지 보조 명도 | `typography::FONT_MAIN_NAV`, `theme::NAV_HEIGHT`, `HEADER_HEIGHT` |
| 화면 제목 | **20pt** | 공통 제목 줄 | 왼쪽, 주요 강조 | `typography::FONT_PAGE_HEADING` |
| 하위 관리 탭 | **16pt** | 버튼 **38pt** | 선택 회색 배경, 나머지 보조 명도 | `FONT_MANAGEMENT_TAB`, `MANAGEMENT_TAB_HEIGHT`, `components::management_tabs` |
| 섹션 제목 | **16pt** | 도움말과 같은 제목줄 | 왼쪽, 굵게 | `FONT_SECTION_HEADING` |
| 주요 본문·표 데이터 | **14pt** | 표는 목록 역할에 따라 **42pt/행** 기준 | 식별 텍스트 왼쪽, 선택/설정 가운데 | `FONT_BODY`, `FREIGHT_ASSIGNMENT_ROW_HEIGHT` |
| 관리 표 헤더 | **14pt** | **36pt** 기준 | 데이터 유형별 아래 정렬 규칙 | `freight_table_header_galley`, `MANAGEMENT_TABLE_HEADER_HEIGHT` |
| 일반 입력 | 해당 공통 서체/필드 역할 | **36pt** | 한글·수치의 세로 기준선 일치 | `theme::INPUT_HEIGHT` |
| 일반 작업 버튼 | **13pt** (중요 버튼은 기존 역할 적용) | standard **34pt** | 주요/보조/위험 역할별 명도 | `theme::ButtonRole` |
| 보조 설명·메타데이터 | **12~13pt** | 콘텐츠에 종속 | 기본 데이터보다 낮은 명도 | `typography.rs` |

- 표 헤더를 본문보다 작게 하지 않는다. 본문이 14pt인 관리 테이블의 헤더도 14pt로 한다.
- 글씨 크기와 위치를 독립 숫자로 보정하지 말고 같은 역할 토큰과 글자 기준선·패딩을 재사용한다.
- 상위 메뉴를 키웠다고 하위 탭을 다시 축소하지 않는다. 중요도는 크기 **외에 위치·선택색·표면**으로 구분한다.
- 한국어 UI, 브랜드, 숫자용 서체 계열은 `typography.rs`의 기존 역할을 유지한다. 폰트 파일을 저장소/배포본에 포함하지 않는다.

## 3. 분리형 KPI 카드 — 숫자 우선

**통계 카드를 사용하는 관리 화면**에 적용한다. 없는 화면에 의미 없는 카드를 추가하지 않는다.

| 역할 | 기준 | 규칙 |
| --- | --- | --- |
| 카드 그룹 | 독립 카드 여러 개 | 레퍼런스는 4개. 모든 화면에 4개를 강제하지 않는다. |
| 카드 기본 폭/높이 | **228 × 80pt** (레퍼런스) | 폭은 실데이터 길이·창 폭에 따라 조정 가능; 핵심은 글꼴 비례 내부 구조 |
| 큰 숫자 | **28pt**, 강조 글꼴 | **상단 중앙**, 자리수 증가에도 정렬 유지 |
| 아래 항목명 | **13pt**, 보조색 | **하단 중앙**, 숫자보다 덜 강조 |
| 숫자-라벨 간격 | **2pt** | 기본 2줄, 임의 겹침·여백 낭비 금지 |
| 내부 패딩 | 좌우 **16pt**, 상하 **12pt** | 텍스트 크기에 비례해 조정. 실제 높이 = 숫자 행 34 + 라벨 행 18 + 간격 2 + 상하 패딩 24 + 테두리 2 = **80pt** |
| 카드 사이 | **8pt** | 왼쪽부터 배치, 폭이 부족할 때는 **카드 단위**로 줄바꿈 |

- 운임 화면은 `등록 상품 / 그룹 지정 완료 / 그룹 미지정 / 배송 그룹` 4개 분리 카드를 유지한다.
- 단위 **'개'를 큰 숫자 옆에 반복하지 않는다**(레퍼런스 방식). 다른 업무에서 단위가 필수라면 의미를 훼손하지 않도록 별도로 설계한다.
- 숫자를 강조하려고 카드 외곽선·의미 없는 배지를 반복해서 강조하지 않는다. 상태색은 실제 의미에만 사용한다.

## 4. 섹션·검색·일괄 작업

- 섹션은 **제목(필요하면 ? 도움말) → 한 줄 도구 영역 → 구분선 → 표 헤더 → 목록** 순서. 중복 안내문이나 불필요한 저장 푸터를 추가하지 않는다.
- 검색/필터는 **왼쪽**, 선택 건수·일괄 대상·적용 동작은 **오른쪽** 한 줄로 묶는다. 독립된 '검색' 텍스트 레이블은 검색창의 플레이스홀더가 충분히 설명한다면 생략한다.
- 우측 도움말 아이콘은 툴바 경계에 붙이지 말고 **최소 8pt 여유**를 확보해 원형 테두리가 잘리지 않도록 한다.
- 실제 화면에서 같은 역할의 간격은 **4/8/12/16/24pt** 공통 공간 토큰 중 하나를 사용한다. 섹션과 통계 사이에는 일관된 여백을 두되 egui 기본 item spacing을 중복 합산하지 않는다.
- 패널 테두리는 주 섹션의 외곽 1회, 안쪽 연속 행은 얇은 선/교차 명도만 사용한다. 같은 섹션 안에 중복 카드 테두리를 남발하지 않는다.
- 반복 행의 부가 버튼은 `TableSecondary`처럼 **어두운 배경·보조색·은은한 테두리**를 사용하되, 동일 역할의 클릭 대상 높이는 유지한다. 중요한 일괄 작업 버튼과 똑같이 강조하지 않는다.
- 실제 자동저장인 기능에는 형식적인 '변경 저장', '그룹 지정 저장', 불필요한 변경 확인 팝업을 새로 넣지 않는다.

## 5. 공통 목록 표: 정렬·열 폭·행·가독성

### 5.1 정렬

| 열의 의미 | 헤더 | 본문 |
| --- | --- | --- |
| 선택 체크박스 | 가운데 | 가운데 |
| 상품명·거래처명·주소·색상/옵션·카테고리 등 텍스트 | **왼쪽** | **왼쪽** |
| 그룹 선택·상태 표시·작업 버튼 | 가운데 | 컨트롤 가운데, 상태 성격에 따라 의미 있는 정렬 |
| 수량·금액 등 수치 | **오른쪽** | **오른쪽**, 숫자 정렬 유지 |

- 헤더 텍스트는 본문과 **같은 왼쪽 시작선**을 사용한다(레퍼런스의 텍스트 셀: 양쪽 6pt 패딩, 시작점 +6pt).
- 정렬 가능한 **헤더의 텍스트 오른쪽에 화살표**를 배치한다. 전체 열이 아니라 **제목+아이콘+간격+양옆 패딩**을 읽을 수 있어야 하며 클리핑 금지.
- 정렬은 **기본(↕) → 오름차순(▲) → 내림차순(▼) → 기본**으로 순환한다. 실제 정렬 가능한 데이터 열에만 적용; 체크박스/설정 버튼 열에 정렬을 억지로 만들지 않는다.
- 검색/필터 **전체 결과**에 정렬 후 가상 렌더링한다. 기본순서는 해당 업무에서 확정한 순서(운임 상품: 그룹 미지정 우선)로 복귀한다.
- 헤더는 상품 행의 수직 스크롤에 따라 위로 사라지지 않고 **고정**돼야 한다.

### 5.2 밀도와 열 폭

- 기본적으로 **상품·거래처 등 데이터 1개당 1행**. 데이터 길이/일부 버튼 유무에 따라 행마다 높이가 줄거나 늘지 않도록 해당 표의 논리 행 높이(레퍼런스 42pt)를 유지한다.
- 상품명은 충분한 폭을 확보하지만 화면의 모든 여유 폭을 무조건 차지하지 않는다. 색상/옵션·카테고리·헤더 정렬 아이콘도 읽을 수 있는 최소 폭을 확보한다.
- *운임 관리 편성 표만의 현행 기본 6열 수치*: 선택 44 / 상품명 218 / 색상·옵션 104 / 카테고리 258 / 배송 그룹 150 / 설정 128pt, 열 간격 각 8pt, 최소 합계 **942pt**. **이 숫자를 다른 관리 표에 일괄 복사하지 않는다.** 데이터 의미·최장값·컨트롤 최소폭을 분석한 후 화면별 열 비율을 정한다.
- 실제 남는 폭 배분과 세로 스크롤바 예약 폭을 **헤더와 데이터 동일한 좌표계에서 계산**한다. 창 폭이 충분할 때 불필요한 가로 스크롤을 만들지 않는다.
- 가로폭이 정말 부족할 때만 표 내부 가로 스크롤 허용; 헤더/셀/드롭다운 너비를 제각각 바꾸거나 한 행을 여러 줄로 늘려서 해결하지 않는다.
- 표 기본 행 `#181818`, 교차 행 `#1e1e1e` (2.5단계), 헤더 `#303030`, 구분선 `#3f3f3f` 계열. 구분선은 보이게, 교차 명도는 과하지 않게 유지한다.

### 5.3 카테고리·보조 정보

- **상위 경로는 낮은 명도**, **마지막 카테고리는 14pt 굵게/더 높은 명도**. 같은 행에서 폰트 크기를 뒤섞지 않는다.
- 경로가 길면 **앞쪽 상위 경로부터 생략**하고 마지막 분류(leaf)를 우선 보존한다. 예: `… > 보면대 > 이동형 보면대`. 전체 원문은 호버 등으로 확인 가능해야 한다.
- 실제 글꼴(상위 경로 보조 + 마지막 경로 Bold)로 폭을 측정한 후 앞부분을 생략한다. 단순 글자 수 컷·끝부분 생략 금지.
- 반복되는 상태 문구가 작업에 도움이 되지 않으면 숨기거나 별도 상세로 이동한다. 설정 버튼도 필요한 행에만 표시하고, 숨겨도 **행의 물리적 높이는 유지**한다.

## 6. 스크롤·상태·클리핑

- 스크롤바는 상시 확인 가능한 **solid** 형태: 레퍼런스 `bar_width=10pt`, `handle_min_length=44pt`, 내·외측 여백 각각 4pt. 가로/세로 스크롤 가능 여부는 실제 콘텐츠에 따른다.
- 스크롤바의 할당 영역과 실제 표 가로폭을 함께 계산해 버튼·마지막 열·원형 도움말 아이콘이 잘리지 않도록 한다.
- 가상 스크롤은 전체 데이터 개수를 기준으로 행을 분할 렌더링하되 화면상 행 좌표는 **인덱스×고정 행 높이**로 안정화한다. 옵션/버튼이 사라져도 체크박스·다음 행·드롭다운이 밀리면 실패다.
- 오른쪽 도움말, 드롭다운 클릭 영역, 첫 행, 헤더 정렬 아이콘, 하단 마지막 행을 모두 스크롤 중 확인한다.
- 빈 결과에도 해당 표 헤더·검색 영역이 유지되고, 로딩/오류가 행 높이나 섹션 위치를 멋대로 변경하지 않게 한다.

| 각 `*_manager.rs` 화면 | **실제 업무에 필요한** 필드·열·검색 필터·정렬 키·편집/저장 연결만 |

**화면별 예외(자동 획일화 금지)**

- 접수 화면은 도킹·카카오톡·발주원문·수취인·원터치·4단계 정보 위계와 고정 분할 비율을 유지한다.
- 모달/확인창은 [별도 모달 계약](modal-design-system.md)과 최신 egui 팝업 계약을 따른다.
- 가격·거래처 주소·주문 품목 등 데이터 구조가 다른 표에 6열/942pt 규격을 복사하지 않는다.
- 그룹 소속 상품의 기본운임 버튼 숨김, 운임 그룹 선택 즉시 저장 등은 **운임 업무 전용 규칙**이다. 다른 화면의 저장 정책에 적용하지 않는다.
- 새 화면을 만들기 전에 **원래 구현/승인된 기능·문구·중요도**를 먼저 조사한다. 외관을 맞춘다는 이유로 기능 삭제·임의 모달·새 업무 값·중복 저장 버튼을 추가하지 않는다.

## 7.1 관리 팝업 공통 버튼 배치 (2026-11-20 최신 승인)

- 팝업에는 기본 윈도우 X 버튼이나 하단 `취소`·`닫기`를 중복 배치하지 않는다. `components::modal_header`를 사용해 **왼쪽에 제목 / 우상단에 텍스트 `취소`·`닫기`**를 놓는다.
- 조회 전용은 `닫기`, 신규 작성·편집 및 위험 작업 확인은 `취소`를 사용한다. 이 버튼은 기존 닫기 또는 미저장 확인 절차를 호출한다.
- 하단 오른쪽에는 해당 팝업의 **최종 실행 버튼**을 둔다. 별도 `저장 안 함` 등 선택지는 실행 버튼 왼쪽, 편집창에서의 독립 삭제 작업은 하단 왼쪽으로 분리한다. 8pt 버튼 간격과 기존 역할별 버튼 크기를 유지한다.
- 레퍼런스의 요약 카드·상품 목록 밀도는 모달에 무조건 복제하지 않는다. 팝업은 업무에 필요한 필드와 선택지만 표시하고, 공통 중앙 정렬 및 카카오톡 제외 작업 영역 규칙을 따른다.
## 8. 다른 탭으로 적용하는 순서 / 완료 판정

1. 대상 화면의 **상위 메뉴 → 제목 → 하위 탭 → 통계(있는 경우) → 섹션 → 도구줄 → 표/상세**를 분해한다.
2. 같은 역할을 위 표의 공통 토큰/컴포넌트에 매핑한다. **화면별 업무 예외와 기존 값**은 별도 기록한다.
3. 기존 수치/CSS를 그대로 이식하지 않고, 이미 적용된 공통 토큰과 충돌하는 지역별 하드코딩·중복 패딩만 제거한다.
4. 정보가 1행/1건인지, 열의 헤더 정렬·데이터 정렬·좌표가 같은지, 문자열과 정렬 아이콘이 잘리지 않는지 확인한다.
5. 표시/로딩/빈 목록/다량(수천~수만)·선택/비선택·저장중/오류·스크롤의 **실제 상태**에서 렌더링을 확인한다.
6. 마우스 클릭, 정렬, 체크박스 선택, 드롭다운, 저장/수동 취소, 팝업 이탈까지 기존 업무 결과를 비교한다.
7. **소스 수정 / 해당 대상 타깃 빌드 / Windows 실화면 / 업무 동작**을 각각 독립적으로 보고한다. 하나만 통과한 상태에서 전체 적용 완료라고 보고하지 않는다.

**적용 대상:** 상품 관리(카테고리/모델군/별칭/브랜드 포함), 거래처 관리, 운임 관리(배송 그룹 편성/관리/이력), 주문 내역, 엑셀 관리, 일일 결산, 설정. 접수는 공통 역할만 공유하며 자체 도킹 계약을 우선한다.

**현시점 작업 범위:** 운임 관리의 사용자 승인 화면을 토대로 **공통 UI 수칙만 재확정**한다. 다른 탭 전체를 자동 변경/검수 완료했다고 주장하지 않는다.
