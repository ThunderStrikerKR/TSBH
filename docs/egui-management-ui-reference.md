# BANDO HUB — egui 관리 화면 공통 UI 기준 (2026-11-20 확정)

> **61차 정식 SSOT 우선(2026-11-21):** 두 공동 마스터의 공통 치수·색상·화면별 예외는 [관리 UI 정식 단일 규격](egui-management-ui-ssot.md)과 해당 Rust 토큰을 우선 적용한다. 이 문서의 나머지는 레퍼런스 화면의 업무별·시각적 설계 근거이며 독립 수치 원본이 아니다.

> **기준 화면:** 사용자가 2026-11-20 최종 승인한 **운임 관리 → 배송 그룹 편성** 화면(상단 메뉴·하위 탭·4개 분리 통계 카드·상품 목록이 함께 보이는 캡처).
>
> **상태:** **새로운 관리 화면 구현·수정의 디자인 기준으로 확정.** 이 문서가 생성되었다고 다른 탭에 일괄 적용된 것은 아니다. 기존 화면의 실제 적용·Windows 검수는 화면마다 별도로 기록한다.
>
> **우선순위:** 최신 명시적 사용자 지시 → 이 문서(egui 공통 관리 UI 역할) → [egui UI 재구축 계약](egui-ui-design-contract.md)의 나머지 기능·화면별 예외 → React/CSS의 과거 이식값. Rust 업무·저장 정책은 시각적 규격 변경으로 덮어쓰지 않는다.

> **임시 적용 — 둥근 `?` 도움말 전면 비활성화(2026-11-21):** 사용자의 지시에 따라 현재 Rust/egui 앱의 모든 원형 도움말 아이콘을 숨기고, 호버·클릭·팝업을 중단한다. `egui-app/src/settings_help.rs`의 `HELP_ICONS_ENABLED = false`가 유일한 제어점이다. 설명 데이터와 호출 위치는 나중에 전면 검수 후 다시 적용하기 위해 보존한다. 아래 도움말 배치·간격 수칙은 **재활성화 후 검수할 참고 규격**이며 지금 화면에서 아이콘을 새로 표시하라는 뜻이 아니다. 업무 데이터의 `?` 또는 도움말이 아닌 상태 표시는 변경 대상이 아니다.

## 1. 레퍼런스에서 확정한 방향

1. **구조적 위계:** 전역 내비게이션 → 화면 제목 → 하위 탭 → 필요할 때만 요약 카드 → 실무 섹션(제목/도구줄/표) 순서. 상위 메뉴를 크게 하고 하위 탭을 지나치게 줄이지 않는다. 둘의 활성 배경색을 구분한다.
2. **분리된 정보 블록:** 요약 수치가 여러 개일 때는 각각 **별도 카드**로 유지하고, 한 개의 통계 막대로 합치지 않는다. 숫자를 위에 크게, 항목명은 아래에 작게 표시한다. 카드 개수·값은 업무에 따라 달라진다.
3. **한 줄 데이터와 동일한 좌표:** 목록은 기본적으로 **항목 1건=1행**. 헤더-본문의 열 경계와 시작선, 체크박스/버튼의 세로 중심, 구분선, 스크롤 위치가 같은 좌표계에 있어야 한다.
4. **업무 정보 우선:** 사용자 식별 데이터(상품명·거래처명 등)를 가장 읽기 쉽게 두고, 상태·반복 버튼은 보조 위계로 내린다. 의미가 중복되는 열·상태 안내·저장 버튼을 임의로 추가하지 않는다.
5. **읽을 수 있는 스크롤:** 스크롤바는 호버하지 않아도 표시되는 **solid/nonfloating** 계열을 사용한다. 데이터·버튼을 덮거나 첫 행을 늘리거나 아래 행을 압축해서는 안 된다.
6. **실제 실행 화면이 검수 기준:** 소스·문서·CI 통과를 Windows 실화면 합격으로 간주하지 않는다.

## 2. 공통 역할별 크기와 텍스트

단위는 egui의 논리 point(pt)이며 실제 Windows DPI/배율 검수가 별도로 필요하다.

| UI 역할 | 글씨 | 높이/구조 | 기본 정렬·강조 | 코드 소유권 |
| --- | --- | --- | --- | --- |
| 상단 전역 내비게이션 | **18pt** | 버튼 **44pt**, 전역 바 **62pt** | 선택 파란 배경, 나머지 보조 명도 | `typography::FONT_MAIN_NAV`, `theme::NAV_HEIGHT`, `HEADER_HEIGHT` |
| 화면 제목 | **20pt** | 공통 제목 줄 | 왼쪽, 주요 강조 | `typography::FONT_PAGE_HEADING` |
| 하위 관리 탭 | **16pt** | 버튼 **38pt** | 선택 회색 배경, 나머지 보조 명도 | `FONT_MANAGEMENT_TAB`, `MANAGEMENT_TAB_HEIGHT`, `components::management_tabs` |
| 섹션 제목 | **16pt** | 도움말과 같은 제목줄 | 왼쪽, 굵게 | `FONT_SECTION_HEADING` |
| 주요 본문·표 데이터 | **14pt** | 표는 목록 역할에 따라 **42pt/행** 기준 | 식별 텍스트 왼쪽, 선택/설정 가운데 | `FONT_BODY`, `FREIGHT_ASSIGNMENT_ROW_HEIGHT` |
| 관리 표 헤더 | **14pt** | **36pt** 기준 | 데이터 유형별 아래 정렬 규칙 | `freight_table_header_galley`, `MANAGEMENT_TABLE_HEADER_HEIGHT` |
| 일반 입력 | 해당 공통 서체/필드 역할 | **36pt** | 한글·수치의 세로 기준선 일치 | `theme::INPUT_HEIGHT` |
| 일반 작업 버튼 | **13pt** (중요 버튼은 기존 역할 적용) | standard **34pt** | 주요/보조/위험 역할별 명도 | `theme::ButtonRole` |
| 보조 설명·메타데이터 | **12~13pt** | 콘텐츠에 종속 | 기본 데이터보다 낮은 명도 | `typography.rs` |

- 표 헤더를 본문보다 작게 하지 않는다. 본문이 14pt인 관리 테이블의 헤더도 14pt로 한다.
- 글씨 크기와 위치를 독립 숫자로 보정하지 말고 같은 역할 토큰과 글자 기준선·패딩을 재사용한다.
- 상위 메뉴를 키웠다고 하위 탭을 다시 축소하지 않는다. 중요도는 크기 **외에 위치·선택색·표면**으로 구분한다.
- 한국어 UI, 브랜드, 숫자용 서체 계열은 `typography.rs`의 기존 역할을 유지한다. 폰트 파일을 저장소/배포본에 포함하지 않는다.

### 상단 여백·정렬 — 운임 관리 최종 승인 추가 (2026-11-21)

- 페이지 제목은 작업영역 좌측에서 **16pt**, 상단에서 **최종 16pt**(이미 존재하는 6pt 외곽 여백 포함). 상단 메뉴/접수 페이지의 전역 프레임은 수정하지 않는다.
- 페이지 제목, 도움말, 우측 메타데이터, 하위 탭 및 실제 KPI 카드의 좌측 내용 시작선은 16pt로 통일한다. 제목→탭 **8pt**, 탭→KPI **12pt**, KPI→큰 박스 **16pt**를 운임 관리에서 승인한 세로 리듬으로 사용한다.
- 탭·KPI가 없는 화면은 **없는 요소를 만들지 않는다**. 제목과 기존 필터/업무 도구만 유지하고 남는 공간을 최종 상단 요소와 첫 큰 박스 사이에 둔다.
- **큰 박스는 59차 외곽 위치 표준화 기준 유지**. 상단 콘텐츠의 들여쓰기는 큰 박스 테두리의 이동이나 테이블 내부 여백 변경을 뜻하지 않는다.
- 실제 화면별 적용 파일 및 예외는 [관리 화면 수칙](management-layout-rules.md)의 59차 추가 확정을 따른다.

## 3. 분리형 KPI 카드 — 숫자 우선

**통계 카드를 사용하는 관리 화면**에 적용한다. 없는 화면에 의미 없는 카드를 추가하지 않는다.

| 역할 | 기준 | 규칙 |
| --- | --- | --- |
| 카드 그룹 | 독립 카드 여러 개 | 레퍼런스는 4개. 모든 화면에 4개를 강제하지 않는다. |
| 카드 기본 폭/높이 | **228 × 80pt** (레퍼런스) | 폭은 실데이터 길이·창 폭에 따라 조정 가능; 핵심은 글꼴 비례 내부 구조 |
| 큰 숫자 | **28pt**, 강조 글꼴 | **상단 중앙**, 자리수 증가에도 정렬 유지 |
| 아래 항목명 | **13pt**, 보조색 | **하단 중앙**, 숫자보다 덜 강조 |
| 숫자-라벨 간격 | **2pt** | 기본 2줄, 임의 겹침·여백 낭비 금지 |
| 내부 패딩 | 좌우 **16pt**, 상하 **12pt** | 텍스트 크기에 비례해 조정. 실제 높이 = 숫자 행 34 + 라벨 행 18 + 간격 2 + 상하 패딩 24 + 테두리 2 = **80pt** |
| 카드 사이 | **8pt** | 왼쪽부터 배치, 폭이 부족할 때는 **카드 단위**로 줄바꿈 |

- 운임 화면은 `등록 상품 / 그룹 지정 완료 / 그룹 미지정 / 배송 그룹` 4개 분리 카드를 유지한다.
- 단위 **'개'를 큰 숫자 옆에 반복하지 않는다**(레퍼런스 방식). 다른 업무에서 단위가 필수라면 의미를 훼손하지 않도록 별도로 설계한다.
- 숫자를 강조하려고 카드 외곽선·의미 없는 배지를 반복해서 강조하지 않는다. 상태색은 실제 의미에만 사용한다.

## 4. 섹션·검색·일괄 작업

- 섹션은 **제목(업무상 필요할 때만) → 한 줄 도구 영역 → 구분선 → 표 헤더 → 목록** 순서. 상단 메뉴/하위 탭만으로 업무가 식별되는 배송 그룹 편성에서는 중복된 `상품별 배송 그룹 지정` 제목을 제거하고 검색 도구줄부터 시작한다. 중복 안내문이나 불필요한 저장 푸터를 추가하지 않는다.
- 검색/필터는 **왼쪽**, 선택 건수·일괄 대상·적용 동작은 **오른쪽** 한 줄로 묶는다. 독립된 '검색' 텍스트 레이블은 검색창의 플레이스홀더가 충분히 설명한다면 생략한다.
- 우측 도움말 아이콘은 툴바 경계에 붙이지 말고 **최소 8pt 여유**를 확보해 원형 테두리가 잘리지 않도록 한다.
- 실제 화면에서 같은 역할의 간격은 **4/8/12/16/24pt** 공통 공간 토큰 중 하나를 사용한다. 섹션과 통계 사이에는 일관된 여백을 두되 egui 기본 item spacing을 중복 합산하지 않는다.
- 패널 테두리는 주 섹션의 외곽 1회, 안쪽 연속 행은 얇은 선/교차 명도만 사용한다. 같은 섹션 안에 중복 카드 테두리를 남발하지 않는다.
- 반복 행의 부가 버튼은 `TableSecondary`처럼 **어두운 배경·보조색·은은한 테두리**를 사용하되, 동일 역할의 클릭 대상 높이는 유지한다. 중요한 일괄 작업 버튼과 똑같이 강조하지 않는다.
- 실제 자동저장인 기능에는 형식적인 '변경 저장', '그룹 지정 저장', 불필요한 변경 확인 팝업을 새로 넣지 않는다.

### 4.1 공통 드롭다운의 텍스트·화살표 수직 정렬 (2026-11-21)

- 주문 내역의 `접수일 기준 / 입금일 기준`, 운임 관리의 `전체 상품`, 일괄 배송 그룹 선택, 각 상품 행의 `그룹 선택`은 모두 `components::management_dropdown`을 사용한다. 각각 별도의 y-offset을 두지 않는다.
- 기존 **34pt 트리거 높이·좌측 텍스트 여백 12pt·우측 화살표 전용 30pt·중간 구분선**을 유지한다. 이번 수정으로 너비·높이·헤더·행 위치나 팝업 항목/저장 동작을 변경하지 않는다.
- 기존 14pt Body 글리프는 22pt 줄 높이 상자의 중앙에 놓아도 실제 화면에서는 다소 위로 보인다. 공통 캡션 위치는 **갈리 크기 중심 정렬 + 2.0pt 시각 보정**으로 통일한다. 보정값의 소유권은 `typography::MANAGEMENT_DROPDOWN_TEXT_OPTICAL_Y`이며 개별 화면에서 재보정하지 않는다.
- **2026-11-21 최종 정정(사용자 요청):** 앞서 드롭다운을 14×12pt로 키운 변경은 **롤백**하고, **기존 10×5pt 선형 V 화살표·선 굵기 1.8pt·하향 시각 보정 -1pt**를 유지한다. 화살표의 방향만 다른 날짜 이동 `‹/›`와 접기·펼치기 메뉴도 **같은 벡터 도형을 회전해서 사용**한다. 날짜 입력창과 드롭다운의 표면색 통일 **`#292929`은 유지**한다. 드롭다운 트리거 34pt·우측 전용 영역 30pt·구분선·실제 선택 동작은 그대로다.
- **2026-11-21 필터 배경색 통일:** 공통 `components::management_dropdown`의 기본 배경을 `theme::RAISED`(`#303030`)에서 **`theme::INPUT`(`#292929`)**으로 바꿔, 주문 내역의 날짜 기준 드롭다운과 시작·종료일 입력창의 표면색을 일치시킨다. 이 컴포넌트를 사용하는 `전체 상품` 및 배송 그룹 선택도 필터/입력 역할로 같은 색을 사용한다. `전체 날짜`처럼 실행 동작을 하는 일반 버튼은 기존 `ButtonRole::Standard`의 `theme::RAISED`(`#303030`)를 유지한다. 드롭다운·날짜 컨트롤의 크기/배치·화살표·선택 동작은 변경하지 않는다.
- **2026-11-21 활성/비활성 구분 최종 확정:** 이전의 '활성·비활성 배경 동일' A안은 사용자 후속 결정으로 **철회**한다. 활성 드롭다운은 `#292929`, 비활성 드롭다운은 `#1E1E1E`(`theme::MANAGEMENT_DROPDOWN_DISABLED_BG`)로 통일한다. 비활성 텍스트·화살표는 `#7C7C7C`, 테두리는 `#373737`. 공통 버튼의 `Standard`와 `TableSecondary` 역할도 비활성일 때 `#1E1E1E` 배경과 같은 낮은 명도를 사용한다. 활성 버튼은 기존 배경·색상을 유지한다. 비활성 여부는 명시적 플래그와 상위 `Ui`의 활성 여부를 함께 평가한다. 클릭·저장·선택 기능, 높이·패딩·화살표 좌표는 바꾸지 않는다.
- 소스 반영과 Windows 실화면 검수는 별개다. **100%/125%/150% 배율**, 활성·비활성 상태, 긴 선택 문구, 행 스크롤 시 글자와 화살표의 실제 픽셀 정렬을 확인한 후 최종 시각 통과를 판정한다.

### 4.2 접기·펼치기 화살표 전수 공통화 (2026-11-21)

- 확인 범위: 최신 Rust/egui 화면 소스 `egui-app/src/*.rs` 전체. 접기 기능은 **처리 중인 주문, 주문 내역, 카테고리 트리, 상품 가격 변경 이력, 거래처 별칭/변경 이력, 운임 기준 이력, 설정의 원문 감사 기록**에서 확인한다.
- 같은 의미의 접힘/펼침은 `components.rs`의 단일 벡터 도형을 사용한다. **접힘 → 오른쪽, 펼침 → 아래쪽**, 선 굵기 1.8pt, 기본 가로폭 10pt. `paint_management_chevron`은 고정 상태, `paint_collapsing_header_icon`은 egui의 애니메이션 개방도에 맞춰 같은 도형을 회전시킨다.
- 주문 내역의 채워진 삼각형, 카테고리 트리의 별도 1.5pt 선, 처리 중 주문의 별도 소형 화살표, 기본 `CollapsingHeader`의 삼각형은 공통 도형으로 교체한다. 기존 업무상 접기 대상·계층 구조·데이터 표시·상태 저장과 클릭 범위는 유지한다.
- 주문 내역의 상품 요약은 화살표의 끝점과 글자가 겹치지 않게 상품 셀 안에서 **왼쪽 20pt** 텍스트 시작선을 확보한다. 행 높이·열 경계·스크롤 좌표는 변경하지 않는다.
- 관리 UI가 아닌 **표 정렬 ↕/▲/▼, 날짜 이동 ↔, 삭제/이전 단계, 달력·폴더 아이콘 등 역할이 다른 기호는 접기 화살표로 강제 교체하지 않는다**. React/CSS 화면은 이 egui 전수 적용의 범위가 아니다.
- 소스 적용과 Windows 실제 화면·DPI·클리핑·키보드/마우스 접기 동작 검수는 분리한다.

## 5. 공통 목록 표: 정렬·열 폭·행·가독성

### 5.1 정렬

| 열의 의미 | 헤더 | 본문 |
| --- | --- | --- |
| 선택 체크박스 | 가운데 | 가운데 |
| 상품명·거래처명·주소·색상/옵션·카테고리 등 텍스트 | **왼쪽** | **왼쪽** |
| 그룹 선택·상태 표시·작업 버튼 | 가운데 | 컨트롤 가운데, 상태 성격에 따라 의미 있는 정렬 |
| 수량·금액 등 수치 | **오른쪽** | **오른쪽**, 숫자 정렬 유지 |

- 헤더 텍스트는 본문과 **같은 왼쪽 시작선**을 사용한다(레퍼런스의 텍스트 셀: 양쪽 6pt 패딩, 시작점 +6pt).
- 정렬 가능한 **헤더의 텍스트 오른쪽에 화살표**를 배치한다. 전체 열이 아니라 **제목+아이콘+간격+양옆 패딩**을 읽을 수 있어야 하며 클리핑 금지.
- 정렬은 **기본(↕) → 오름차순(▲) → 내림차순(▼) → 기본**으로 순환한다. 실제 정렬 가능한 데이터 열에만 적용; 체크박스/설정 버튼 열에 정렬을 억지로 만들지 않는다.
- 검색/필터 **전체 결과**에 정렬 후 가상 렌더링한다. 기본순서는 해당 업무에서 확정한 순서(운임 상품: 그룹 미지정 우선)로 복귀한다.
- 헤더는 상품 행의 수직 스크롤에 따라 위로 사라지지 않고 **고정**돼야 한다.

### 5.2 밀도와 열 폭

- 기본적으로 **상품·거래처 등 데이터 1개당 1행**. 데이터 길이/일부 버튼 유무에 따라 행마다 높이가 줄거나 늘지 않도록 해당 표의 논리 행 높이(레퍼런스 42pt)를 유지한다.
- 상품명은 충분한 폭을 확보하지만 화면의 모든 여유 폭을 무조건 차지하지 않는다. 색상/옵션·카테고리·헤더 정렬 아이콘도 읽을 수 있는 최소 폭을 확보한다.
- *운임 관리 → 배송 그룹 편성의 확정 기본 6열 수치*: 선택 44 / 상품명 **202** / 색상·옵션 104 / 카테고리 258 / 배송 그룹 150 / 설정 **144pt**, 열 간격 각 8pt×5, 최소 합계 **942pt**. **2026-11-21 CONFLICT-002에서 현행 `theme::FREIGHT_ASSIGNMENT_COL_WIDTHS`를 최종 기준으로 확정했다.** 남는 폭은 상품명 64%, 카테고리 36%로 배분한다. **이 숫자를 다른 관리 표에 일괄 복사하지 않는다.** 데이터 의미·최장값·컨트롤 최소폭을 분석한 후 화면별 열 비율을 정한다.
- 실제 남는 폭 배분과 세로 스크롤바 예약 폭을 **헤더와 데이터 동일한 좌표계에서 계산**한다. 창 폭이 충분할 때 불필요한 가로 스크롤을 만들지 않는다.
- 가로폭이 정말 부족할 때만 표 내부 가로 스크롤 허용; 헤더/셀/드롭다운 너비를 제각각 바꾸거나 한 행을 여러 줄로 늘려서 해결하지 않는다.
- 표 기본 행 `#181818`, 교차 행 `#1e1e1e` (2.5단계), 헤더 `#303030`, 구분선 `#3f3f3f` 계열. 구분선은 보이게, 교차 명도는 과하지 않게 유지한다.

### 5.3 카테고리·보조 정보

- **상위 경로는 낮은 명도**, **마지막 카테고리는 14pt 굵게/더 높은 명도**. 같은 행에서 폰트 크기를 뒤섞지 않는다.
- 경로가 길면 **앞쪽 상위 경로부터 생략**하고 마지막 분류(leaf)를 우선 보존한다. 예: `… > 보면대 > 이동형 보면대`. 전체 원문은 호버 등으로 확인 가능해야 한다.
- 실제 글꼴(상위 경로 보조 + 마지막 경로 Bold)로 폭을 측정한 후 앞부분을 생략한다. 단순 글자 수 컷·끝부분 생략 금지.
- 반복되는 상태 문구가 작업에 도움이 되지 않으면 숨기거나 별도 상세로 이동한다. 설정 버튼도 필요한 행에만 표시하고, 숨겨도 **행의 물리적 높이는 유지**한다.

## 6. 스크롤·상태·클리핑

- 스크롤바는 상시 확인 가능한 **solid** 형태: 관리 **표 전용** `management_table_scroll_style()`은 `bar_width=10pt`, `handle_min_length=44pt`, **내·외측 추가 여백 각각 0pt**다(CONFLICT-003 A). `management_table_scroll_track_rect()`가 트랙 상단을 **데이터 행 시작과 같은 Y(0pt 간격)**에 연결하고, **배송그룹 편성·주문내역 마스터는 카드 하단 패딩 16pt를 유지하되, 표 본문은 패딩 위에서 종료하고 레일만 11pt 연장해 공통 3pt 광학 보정 후 카드 외곽선 8pt 앞까지 표시한다.** Excel 작성 푸터·편집 상세·복수 표가 있으면 연장값은 역시 0pt로 해당 영역을 보호한다. 기타 화면의 하단 연장 예외는 별도 정책을 따른다. 페이지 일반 스크롤은 별도 스타일을 유지한다.
- 스크롤바의 할당 영역과 실제 **표 헤더·본문 가로폭**을 함께 계산해 버튼·마지막 열·원형 도움말 아이콘이 잘리지 않도록 한다. **CONFLICT-001 C안 승인(2026-11-21):** 도구줄의 오른쪽 끝은 표 데이터 영역 끝이 아니라 **주 카드의 내부 오른쪽 경계**에 맞춘다. 도구줄에는 스크롤바 폭을 차감하지 않으며, 스크롤바 레일 예약은 오직 고정 헤더와 표 본문에만 적용한다. 두 마스터의 오른쪽 도구줄 슬롯은 `components::management_toolbar_trailing_rect`로 계산한다.
- 가상 스크롤은 전체 데이터 개수를 기준으로 행을 분할 렌더링하되 화면상 행 좌표는 **인덱스×고정 행 높이**로 안정화한다. 옵션/버튼이 사라져도 체크박스·다음 행·드롭다운이 밀리면 실패다.
- 오른쪽 도움말, 드롭다운 클릭 영역, 첫 행, 헤더 정렬 아이콘, 하단 마지막 행을 모두 스크롤 중 확인한다.
- 빈 결과에도 해당 표 헤더·검색 영역이 유지되고, 로딩/오류가 행 높이나 섹션 위치를 멋대로 변경하지 않게 한다.

### 6.1 배송 그룹 편성: 표 내부 배치 기준 (2026-11-21)

- 검색/필터·일괄 적용 도구줄은 한 줄로 유지한다. **CONFLICT-005 확정:** 고정 헤더까지의 간격은 **상단 16pt + 구분선 1pt + 하단 4pt = 총 21pt**다(`management_sticky_table_header`). egui 기본 `item_spacing.y`를 중복 적용하지 않는다. 프레임이 하단 8pt를 이미 소비했다면 `management_sticky_table_header_after_inset`으로 **기존 8pt + 추가 8pt + 1pt + 4pt**를 적용한다.
- 표 헤더는 36pt, 행은 42pt. 마지막 2pt 헤더 윤곽선은 헤더 **안쪽**에 포함하되 텍스트·정렬 화살표·전체 선택 체크박스는 남은 34pt의 중심선에 놓는다.
- 기본 운임 설정 **단일 버튼**은 설정 열의 수평 중심축에 일치시킨다. 가로폭을 셀 안쪽에서 확보하되 34pt의 버튼 높이는 42pt 행 전체로 늘리지 않는다. 두 작업 버튼이 함께 나타나는 레거시 행에서는 버튼을 숨기거나 겹치게 만들지 않는다.
- 단일 주 목록 카드의 스크롤 본문은 **툴바·구분선·고정 헤더를 제외한 카드 안쪽 남은 높이**를 사용한다. 목록 자체의 높이를 화면 전체의 60%로 제한해 카드 아래에 불필요한 빈 띠를 남기지 않는다. 페이지 제목·KPI·큰 박스 **외곽 좌표는 그대로 유지**한다.
- **CONFLICT-004 A안 반영:** 단일 주 목록인 주문 내역·상품 목록·거래처 관리·엑셀 관리의 해당 목록에 카드의 남은 높이 계산을 적용했다. Excel의 동적 하단 관리/상세 영역이 열리면 기존 높이 상한을 유지한다. 두 표 이상의 일일 결산, 운임 복수 이력, 좌우 독립 편집형 자동 메시지 화면에는 카드 전체 남은 높이를 일괄 복제하지 않는다.
- 실제 Windows 실행·다중 DPI·키보드/마우스 휠·1건/다량 데이터에 대한 검증은 정적 코드 및 CI 컴파일과 별개다.

**화면별 예외(자동 획일화 금지)**

- 접수 화면은 도킹·카카오톡·발주원문·수취인·원터치·4단계 정보 위계와 고정 분할 비율을 유지한다.
- 모달/확인창은 [별도 모달 계약](modal-design-system.md)과 최신 egui 팝업 계약을 따른다.
- 가격·거래처 주소·주문 품목 등 데이터 구조가 다른 표에 6열/942pt 규격을 복사하지 않는다.
- 그룹 소속 상품의 기본운임 버튼 숨김, 운임 그룹 선택 즉시 저장 등은 **운임 업무 전용 규칙**이다. 다른 화면의 저장 정책에 적용하지 않는다.
- 새 화면을 만들기 전에 **원래 구현/승인된 기능·문구·중요도**를 먼저 조사한다. 외관을 맞춘다는 이유로 기능 삭제·임의 모달·새 업무 값·중복 저장 버튼을 추가하지 않는다.

## 7.1 관리 팝업 공통 버튼 배치 (2026-11-20 최신 승인)

- 팝업에는 기본 윈도우 X 버튼이나 하단 `취소`·`닫기`를 중복 배치하지 않는다. `components::modal_header`를 사용해 **왼쪽에 제목 / 우상단에 텍스트 `취소`·`닫기`**를 놓는다.
- 조회 전용은 `닫기`, 신규 작성·편집 및 위험 작업 확인은 `취소`를 사용한다. 이 버튼은 기존 닫기 또는 미저장 확인 절차를 호출한다.
- 하단 오른쪽에는 해당 팝업의 **최종 실행 버튼**을 둔다. 별도 `저장 안 함` 등 선택지는 실행 버튼 왼쪽, 편집창에서의 독립 삭제 작업은 하단 왼쪽으로 분리한다. 8pt 버튼 간격과 기존 역할별 버튼 크기를 유지한다.
- 레퍼런스의 요약 카드·상품 목록 밀도는 모달에 무조건 복제하지 않는다. 팝업은 업무에 필요한 필드와 선택지만 표시하고, 공통 중앙 정렬 및 카카오톡 제외 작업 영역 규칙을 따른다.
## 7.2 거래처 관리 적용 — 배송 그룹 편성 화면 레퍼런스 (2026-11-20)

- **제목 → 하위 탭 → 단일 거래처 카드**의 레이어를 유지한다. 별도 KPI 카드나 불필요한 성공·상태 배너를 만들지 않는다. 카드 내부는 `등록 거래처` 16pt 섹션 제목과 검색 결과 건수 → 검색/우측 작업 버튼 → 구분선 → 고정 헤더 → 스크롤 목록 순서다.
- **36pt 헤더 + 42pt 고정 거래처 행**: 이름·발송인·거래 조건의 3열 비율은 30/38/32, 최소 표 폭은 900pt. 헤더와 행은 같은 열 시작점·12pt 패딩을 사용하고 표 헤더/주요 내용은 모두 14pt. 등급 배지만 기존 도매/반도매/소매/특수 상태색을 쓰고, 조건·연락처는 낮은 명도의 보조정보로 표시한다.
- **고정 헤더와 정렬**: 가로 스크롤 offset 공유, 세로 스크롤과 독립된 헤더, 기본/오름차순/내림차순/기본 정렬 순환. 정렬 키는 거래처명·주소·가격등급이며, Rust 검색 결과 전부를 화면 표시용으로 정렬한 후 가상 행으로 렌더한다.
- 검색은 왼쪽, 기존 `Excel 관리`·`＋ 거래처 등록`은 오른쪽 한 줄. 이때 검색과 작업 버튼은 같은 36pt 높이의 독립 영역에 정렬하며, 좁은 화면에서만 두 줄. 10pt solid scrollbar를 사용하고 스크롤바 트랙이 목록 내용이나 헤더를 덮지 않도록 좌표와 폭을 예약한다.
- 등록·상세 편집창은 전체 팝업의 **우상단 텍스트 취소 / 하단 우측 실행** 규칙과 기존 미저장·삭제 동작을 따른다. 상품/운임 등 다른 화면의 업무 전용 속성과 레이아웃을 복제하지 않는다.
## 7.3 거래처 관리 / 자동 메시지 편집 (2026-11-20)

- 두 관리 하위 탭은 `상황별 공통 안내`, `잠정 상품 선택 안내`다. 화면 목적은 **목록에서 문구를 선택하고 편집 후 저장**하는 것이므로 배송 그룹 편성의 숫자 KPI 카드를 복사하지 않는다.
- 왼쪽 목록 / 오른쪽 편집 영역의 독립된 2개 기능 블록만 사용한다. 기존 React 메시지 편집의 48pt 선택 행은 공통 `components::management_chooser_row`를 재사용하고, 두 줄(주요 이름·작은 등록 상태)을 안정된 간격으로 정렬한다. 선택 행 상태 배경색·호버는 공통 팔레트에서만 가져온다.
- 페이지/하위탭·섹션 제목·본문·버튼·입력은 배송 그룹 편성과 동일한 20/16/14/13pt 역할과 공통 여백·표면·스크롤바를 사용한다. 오른쪽 미리보기는 편집 결과를 확인하는 별도 기능이므로 낮은 명도의 단일 표면만 쓰고 중복 테두리/안내 카드를 쌓지 않는다.
- 저장 버튼은 편집 푸터 **맨 오른쪽**, 미저장 확인창의 우상단에는 **취소**를 하나만 둔다. 업무 확정은 기존 Rust 검증·백업·설정 CAS로만 수행하고 목록 UI는 저장 여부를 결정하지 않는다.
## 8. 다른 탭으로 적용하는 순서 / 완료 판정

1. 대상 화면의 **상위 메뉴 → 제목 → 하위 탭 → 통계(있는 경우) → 섹션 → 도구줄 → 표/상세**를 분해한다.
2. 같은 역할을 위 표의 공통 토큰/컴포넌트에 매핑한다. **화면별 업무 예외와 기존 값**은 별도 기록한다.
3. 기존 수치/CSS를 그대로 이식하지 않고, 이미 적용된 공통 토큰과 충돌하는 지역별 하드코딩·중복 패딩만 제거한다.
4. 정보가 1행/1건인지, 열의 헤더 정렬·데이터 정렬·좌표가 같은지, 문자열과 정렬 아이콘이 잘리지 않는지 확인한다.
5. 표시/로딩/빈 목록/다량(수천~수만)·선택/비선택·저장중/오류·스크롤의 **실제 상태**에서 렌더링을 확인한다.
6. 마우스 클릭, 정렬, 체크박스 선택, 드롭다운, 저장/수동 취소, 팝업 이탈까지 기존 업무 결과를 비교한다.
7. **소스 수정 / 해당 대상 타깃 빌드 / Windows 실화면 / 업무 동작**을 각각 독립적으로 보고한다. 하나만 통과한 상태에서 전체 적용 완료라고 보고하지 않는다.

**적용 대상:** 상품 관리(카테고리/모델군/별칭/브랜드 포함), 거래처 관리, 운임 관리(배송 그룹 편성/관리/이력), 주문 내역, 엑셀 관리, 일일 결산, 설정. 접수는 공통 역할만 공유하며 자체 도킹 계약을 우선한다.

**현시점 작업 범위:** 운임 관리의 사용자 승인 화면을 토대로 **공통 UI 수칙만 재확정**한다. 다른 탭 전체를 자동 변경/검수 완료했다고 주장하지 않는다.
