# 관리 UI SSOT — 타 화면 실제 적용 기록 (2026-11-21)

> **적용 기준:** `docs/egui-management-ui-ssot.md`, 공동 마스터는 **운임관리 → 배송그룹 편성 / 주문내역**.
> **이번 적용은 두 마스터에서 승인한 동일 역할의 기존 치수를 중앙 소유권에 연결한 것**이며, 모든 화면이 두 마스터와 픽셀 단위로 일치한다는 최종 판정이 아니다.
> **검증:** GitHub `main`의 수정된 소스·함수 호출을 정적으로 재조회했다. Windows 빌드 / 실제 렌더링 / DPI / 업무 회귀테스트는 수행하지 않았다.

## 1. 실제 소스 적용

| 화면 / 세부 영역 | 이번에 연결한 공통 규격 | 보존한 화면별 구조 |
| --- | --- | --- |
| **거래처 관리 → 거래처 목록** | `management_existing_list_table_header`(고정 36pt 헤더와 데이터 너비 계산), `management_toolbar_trailing_rect`(우측 작업 버튼의 카드 내부 끝 정렬) | 거래처 3열, 최소 폭 900pt, 42pt 행, 편집 팝업 및 목록의 기존 패딩 |
| **상품 관리 → 상품 목록** | 동일 공통 고정 헤더, `management_single_stretch_columns`(상품명 열에 남는 폭 배분), 공통 `management_dropdown`(카테고리·브랜드 필터) | 가격 편집 모드의 넓은 입력 셀, 카테고리 기존 280pt 선택창, 경로 축약/전체 경로 호버, 데이터 로직 |
| **엑셀 관리 → 대기/작성 이력 목록** | 동일 공통 고정 헤더, 단일 열 가변 폭 계산, 공통 `MANAGEMENT_COMPACT_ROW_HEIGHT` 42pt | 기존 각 탭의 데이터 열·선택·엑셀 액션·필터/빈 상태 |
| **일일 결산 → 주문/입금 표** | 동일 공통 고정 헤더, 단일 열 가변 폭 계산, 공통 42pt 기본행 | 두 결산 표의 서로 다른 열/숫자 정렬, 날짜 선택·업무 집계 로직 |
| **운임관리 → 그룹 운임표** | 동일 공통 고정 헤더, `management_weighted_columns`(그룹/배송비/메모 잉여 폭 40/20/40) | 6열, 등록/변경 업무 및 기존 액션/세로 구조 |
| **운임관리 → 조합 및 이전 기준 이력** | 동일 공통 고정 헤더, 가중치 기반 공통 열 배분 | 조합/이력별 서로 다른 열·확장 기능·정렬 |
| **주문내역 마스터** | 고정 대표행에서 freight 전용 별칭 대신 의미 기반 `MANAGEMENT_COMPACT_ROW_HEIGHT` 사용. 필터 148pt 토큰 공유 | 7열과 가변 상세행, 날짜 줄바꿈, 마스터 헤더·표 레일 |
| **배송그룹 편성 마스터** | 기존 148pt 필터를 `MANAGEMENT_FILTER_DROPDOWN_WIDTH`에 연결 | 6열, 64/36 잉여 폭, 고정행, 최종 승인 화면 |

## 2. 이미 공통을 사용하므로 레이아웃 변경하지 않은 영역

- **설정:** 상단 제목/탭/첫 카드 기준은 이미 공통 함수 사용. 설정은 세로 다중 카드와 입력폼 역할이어서 42pt 목록표를 강제할 대상이 아님.
- **거래처 → 자동 메시지 편집:** 기존 공통 탭, `section_frame`과 좌우 분리 편집 카드 사용. 독립 두 패널을 단일 표로 합치지 않음.
- **상품관리 내부 모델군/카테고리/별칭/브랜드:** 상품관리 상위 내비게이션과 외곽 기준을 상속하고, 개별 패널은 트리·폼·편집 도구 역할을 유지. 하위 편집 콤보박스를 목록용 필터 드롭다운으로 무차별 전환하지 않음.
- **발주서 상세/접수, 카카오톡 도킹, 그 밖의 비관리 화면:** 두 관리 마스터의 외곽 카드·열 너비를 강제하지 않음.

## 3. 코드 소유권 추가

- `components::management_existing_list_table_header(ui,min_width)`: 기존 일반 관리 목록들의 **36pt 고정 헤더, 실제 데이터 가로폭, 스크롤바 할당 폭**을 한곳에서 계산한다. 여기서는 기존 화면이 가지고 있던 **추가 4pt**를 아직 보존한다.
- `theme::management_weighted_columns`: 화면별 기본 열 폭과 남는 공간의 가중치 배분을 공통화한다.
- `theme::management_single_stretch_columns`: 남는 공간을 한 열에 집중하는 목록(상품, Excel, 결산)에서 위 배분 함수 재사용.
- `theme::MANAGEMENT_FILTER_DROPDOWN_WIDTH=148pt`: 마스터의 날짜 기준/상품 필터와 상품관리 브랜드 필터가 사용한다. **카테고리의 긴 경로는 기존 전용 280pt**를 유지.
- `management_dropdown_option`: 선택 직후 팝업 닫기 규칙을 유지하며 옵션의 `Response`를 노출해 카테고리 전체 경로 호버를 보존한다.

## 4. 사용자 결정이 필요한 충돌 (아직 수정하지 않음)

**CONFLICT-003 — 스크롤바 좌우 여백**
- 두 마스터 표: **레일 좌우 추가 여백 0pt** (목록 데이터 끝과 스크롤 레일을 밀착).
- 기존 거래처/상품/Excel/결산/운임 그룹·이력 목록: 데이터 폭 계산에서 **스크롤바 할당폭 + 추가 4pt**를 보존.
- *결정 필요:* 동일한 목록표 역할에서 두 마스터의 0pt 규격을 전체 적용할지, 기존 목록 전용 4pt 예외를 승인할지. 이번 작업은 기존 실행 좌표를 먼저 보존한다.

**CONFLICT-004 — 표 본문 높이**
- 두 마스터의 단일 주 목록: 카드의 남은 실제 높이까지 스크롤 본문 확장.
- 기존 상품/거래처/Excel/결산/운임 그룹·이력 표: `MANAGEMENT_TABLE_VIEWPORT_FRACTION=0.60` 기반 높이 상한을 사용.
- *결정 필요:* **한 장짜리 목록 카드**에 한해 두 마스터의 카드 남은 높이 정책으로 옮길지, 다른 카드/추가 안내를 위한 현재 상한을 유지할지. 다중 결산 표·설정 편집 패널은 별도 역할이다.

**CONFLICT-005 — 도구줄부터 고정 헤더까지의 수직 리듬**
- 두 마스터: 공통 `management_sticky_table_header`의 **17pt 전환(8+4+1+4)**과 헤더 내부 2pt 윤곽선.
- 다른 목록 화면: 상단 별도 제목/편집 도구·기존 `soft_divider`, 일부 헤더 하단 1pt 선을 사용.
- *결정 필요:* **검색 도구줄→표 헤더가 직접 이어지는 동일 역할**만 17pt 공통 경로로 옮길지, 제목/상태 줄이 있는 목록들의 별도 리듬을 허용할지. 승인 없이 섹션 제목·오류/안내를 없애지 않는다.

## 5. 정적 검수와 한계

- 주요 파일의 공통 함수 호출·토큰 존재 확인. 4개 다른 관리 목록+운임 그룹/이력 테이블이 공통 헤더 함수를 사용.
- 새로운 표 너비 함수는 **이전과 동일한 계산식**을 중앙화한다. 최솟값과 열 배분의 산술 자체는 변경하지 않았고, 고정행은 같은 42pt 역할 토큰을 가리킨다.
- 상품관리의 카테고리·브랜드 필터는 기존 네이티브 `ComboBox`에서 공통 커스텀 드롭다운으로 전환했으므로 **외관/팝업 표시 및 좁은 화면 줄바꿈은 실제 검수가 필요**하다. 브랜드 필터는 148pt로 정렬되고 긴 브랜드명은 호버에서 확인한다.
- 전체 관리 UI가 Windows에서 완전히 동일하게 보이는지는 아직 확인할 수 없다. `CONFLICT-003~005`는 임의로 확정하지 않는다.
