# 2026-11-20 egui 멈춤 수정 및 의심 경로 조사

코드 커밋: `a60b9a083487b618ecac7cd75adfcf7e8d4519ff` (로컬 main). 사용자 요청: 별칭 관리 반복 클릭 후 멈춤 수정, 다른 화면의 의심 경로 조사·보고.

## 확인한 원인과 수정

별칭 관리 `show_page`는 재그리기마다 원본 Rust `alias_problems`를 UI 스레드에서 호출했다. 충돌 검사 내부의 `model_names`는 상품마다 정규식을 재컴파일했다. 마우스 이동·호버·재클릭으로 다시 그려질 때마다 약 4초간 입력 처리가 지연되는 경로다. 분석 시 채취한 메인 스레드는 Windows 메시지 대기에 있었고 WCT에서 순환 대기는 검출되지 않았다. 영구 교착으로 확정한 것은 아니다.

- 네이티브 별칭 규칙의 두 정규식을 `LazyLock`으로 재사용한다. 충돌 판단·오류 문자열·순서·저장 규칙은 바꾸지 않았다.
- 별칭 경고는 상품·별칭 내용이 실제로 바뀔 때만 백그라운드 계산한다. revision이 없거나 유지돼도 내용 변경을 감지한다. 화면 그리기는 캐시만 읽는다.
- 별칭의 상품 선택창은 상품/분류/브랜드 데이터 또는 검색 필터가 바뀔 때만 백그라운드 조회한다. 모델군 등록 가능 상품도 상품 데이터 변경 시에만 재조회한다. 네이티브 질의 결과를 그대로 사용한다.
- 상품 목록·별칭 진단·상품 선택·모델군 조회는 공통 `LatestJob`으로 실행 1개 + 대기 최신 1개만 유지한다. 이전 응답은 세대 번호로 무시한다. 조회 전용이며 저장 작업은 합치지 않는다.
- 개발 빌드는 UI update가 100ms를 초과하면 화면/탭 이름과 소요 시간만 stderr에 기록한다. 사용자 데이터나 새 UI 알림은 추가하지 않는다. GPU present·Windows 메시지 루프의 전체 시간은 이 수치에 포함되지 않는다.

## 검증 게이트

- PATCH: 위 코드 커밋. 기존 미커밋 `src-tauri/Cargo.lock`, 추적되지 않은 lock/target은 커밋하지 않았다.
- UNIT: 최종 egui 전체 172개 중 169 통과, 3 실패. 신규 5개(최신 요청 합치기, 실행 중 무효화, 별칭 캐시 무효화/재사용, 상품 검색 최신 필터/캐시, 모델군 캐시 무효화/재사용)는 통과했다. 별칭 저장 시 기존 ID·과거 주문 보존 테스트도 통과했다.
- 미통과 테스트: `client_directory::tests::live_relational_database_is_read_only_and_exposes_only_names` (phone 필드 단언), `layout::geometry_contract::reference_1920p_columns_do_not_trigger_min_width_clamping` (열 비율), `gateway::shipping_gateway_direct_roundtrip_tests::shipping_gateway_direct_roundtrip` (명시적 fixture DB 미지정). 해당 소스는 수정하지 않았다. 동일 HEAD의 수정 전 전체 테스트를 별도 체크아웃하여 실행하지 않았으므로 이번 기록만으로 세 실패의 선행 여부를 확정하지 않는다.
- DIFF: 수정 전 Rust와 수정 후 Rust 별칭 진단 JSON 완전 동일. TS 전체 차등은 미실행.
- ACTION / WINDOWS: `DEV_WINDOWS_EGUI.cmd`로 새 개발 빌드(14.88초) 재실행. 상품 관리 진입, 별칭 탭 선택 및 2회 클릭, 직후 모델군 전환, 카테고리 진입·보면대 하위 펼치기, 별칭 재진입, 상품 선택창 열기, `709` 검색 결과 갱신, 상품 선택 없이 닫기 관찰. 각 도구 호출은 대략 0.3~0.5초에 화면 갱신을 반환했으나 정밀 입력 지연 벤치마크로 간주하지 않는다. 이 시험 중 100ms 초과 UI update 로그와 panic은 없었다. 저장/삭제/상품 선택은 수행하지 않았다.
- CI: 미실행, GitHub push 미실행. 로컬 main에 반영했고 현재 PC의 새 실행본으로 확인했다.
