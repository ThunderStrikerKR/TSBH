## 문제 3 — 사용자 확정 판단 원칙 (2026-11-28)

1. 같은 발주서에 포함된 여러 수취인 블록은 동일 작성 순서를 따를 가능성이 압도적으로 높다는 사용자 업무 경험을 강한 문서 내 사전 근거로 사용한다. 예: A가 1234이면 B도 1234가 기본 가설이다. 2341 등 상이한 순서가 혼합되는 경우는 희귀하되 배제하지 않는다. 수치 확률은 제공되지 않았으며 임의 설정하지 않는다.
2. 문서 전체의 일관된 패턴을 우선 추론한다. 반복 구조가 명확하면 이를 이용해 모호한 지역 후보를 해석한다. 단일 단서, 단순 거리 차이, 품목 수 변화, 선택 필드 생략만으로 혼합 패턴으로 판단하지 않는다.
3. 명시적 수취인·상품·수량 연결, 원문 구역 등 신뢰할 수 있는 독립적 국소 반증이 있을 때만 해당 구간의 예외를 인정한다. 일관된 패턴은 강한 근거이지 명시적 증거를 무효화하는 절대 제약은 아니다. 반증이 부족하면 기존 기본 판단을 유지하고 실제로 모호한 관계는 현행 확인 절차로 남긴다.
4. 정상 동일패턴 발주서의 기존 정답을 훼손하여 희귀한 혼합 패턴의 성능을 개선하는 변경은 승인하지 않는다. 동일패턴 회귀, 혼합 패턴, 불완전 반복/선택 필드 사례를 구분하여 비교한다. 희귀 사례에 대한 합성 검증은 실측 발생 빈도 증거가 아니다. 18건 전체 정답/고정 기준선 및 관련 회귀 보호를 유지한다.
5. 별도의 혼합패턴 엔진, 새 사용자 UI, 임의 확률이나 과도한 전체 후보 조합은 추가하지 않는다. 기존 공통 특징·귀속 판단 경로를 개선한다.

- 상태: OPEN(미조치), IN_PROGRESS(현재 조치), VERIFYING(코드 반영·검증 대기), RESOLVED(실제 동작과 관련 회귀 및 전체 CI 확인). 검증 실패 시 OPEN/VERIFYING으로 유지하고 실제 실패만 수정한다.

- 07단계 확률 보정 및 결합은 현재 이탈 조치 완료 후 진행한다. 08단계 기존 규격 자료의 재생성·재시작 복구 및 타 경로 동기화, 09단계 승인된 미확정 검증은 별도의 이탈 업무로 중복 생성하지 않는다.
- 기본 가중치 baseline-v1 유지, 최초 78개 범위 유지, main 병합 금지. 해당 문제와 무관한 기능·검증·호환 계층을 추가하지 않는다.
