# 반도허브 상품 360개 모델 표기 취약점 전수조사
- 기준: `ThunderStrikerKR/TSBH` `src-tauri/resources/state-seed.json` (2026-11-18 확인)
- 조사 전체: **360개**, 활성 **358개**, 비활성 **2개**
- 방식: 각 SKU의 `name` 첫 구간 + `modelCodes` + 공식 `code`(웹몰 P코드 제외)를 비교해, `BD` 접두·공백·하이픈·구분기호를 제거한 **비교용 키** 구성. 상품 ID와 실제 모델명은 변경하지 않음
- 상세 결과: [360개 전체 행별 CSV](./38-product-model-spelling-audit-360.csv). 각 행에는 공식 SKU ID, 원본 이름, 비교 키, 충돌 키, 위험 분류 포함

## 전수조사 결과

| 위험 지표 | 해당 SKU 수 |
|---|---:|
| 동일 비교 키가 복수 독립 SKU에 해당 | **115** |
| 구분 기호·중간 공백을 생략한 발주 표기로 바뀔 가능성 | **176** |

| 동일 키 충돌과 구분기호 생략 위험이 모두 존재 | **62** |
| 위 3개 정적 위험 중 적어도 하나 포함 | **240** |
| 별도 정적 위험 징후 없음 | **120** |

- 충돌 비교 키: **41개**, 전체 비교 키: **290개**
- 집계는 **중첩 가능**하며, 모델 표기 관련 정적 위험을 뜻한다. 360개 전부가 실제 인식에 실패했다는 의미는 아니다.
- 일부 SKU는 같은 모델의 색상·규격 등 옵션 차이이며, 다른 SKU는 아예 다른 제품이다. 따라서 구분 기호를 제거한 비교 키를 **자동 확정용 기본키로 사용해서는 안 된다.**
- 모델명 뒤에 사양 설명이 포함된 상품은 코드뿐 아니라 명시된 크기·색상·용도까지 평가해야 한다.

## 권고 및 검증 경계

1. **정확 매칭과 추천 분리:** 기존 Rust 정확 모델/별칭 인식·가격·주문 확정 로직은 유지하고 추천은 해결 절차에만 연결한다.
2. **구분기호 정규화:** 원문 코드와 카탈로그 코드를 `BD` 접두·공백·하이픈 제거 키로 비교하되, 원래 모델 코드와 SKU 식별자는 변경하지 않는다.
3. **근거 점수:** 정확 비교 키 > 동일 거래처의 확정 이력 > 짧은 편집거리(길이 제한) 및 품목/용도 일치. 한글 색상·구성 단서는 독립 확인한다.
4. **충돌 보존:** `Z4`, `GT10`, `NOTEBOOKA`처럼 여러 SKU가 겹치면 모두 제시하고 자동 확정하지 않는다.
5. **오탐 방지:** 독립 코드가 없는 `가방` 한 단어만으로 여러 상품을 임의 추천하지 않는다. 실물/용도 증거 또는 과거 확정 이력이 있을 때 추천한다.

### 검증의 범위
이 자료는 **실제 360개 상품 원본을 전수 파싱한 구조적 취약점 조사**다. 모든 상품마다 임의의 오탈자 주문을 생성하여 Windows UI에서 직접 실행한 전수 E2E 테스트와는 다르다. 회귀 검증은 Rust 후보 엔진과 발주서 사례로 별도 수행한다.
