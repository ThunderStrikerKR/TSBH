# 반도허브 공통 셀 편집 계약

**상태:** 80차 설계 기준. 코드 적용은 화면별로 진행하며 미적용 화면을 완료로 간주하지 않는다.

## 범위
표·반복 행 안에서 값 자체를 직접 편집하는 셀이 대상이다. 접수의 수취인·품목·운임, 수동 분류, 상품 가격표, 처리 중인 주문의 실제 운임을 포함한다. 검색창, 일반 상세 폼, 장문 입력창, 날짜 선택기, 체크박스, 라디오 및 드롭다운은 셀 이동 대상이 아니다.

## 키보드 계약
| 키 | 기본 동작 |
| --- | --- |
| ↑ ↓ ← → | 화면 어댑터가 제공한 명시적 좌표에서 인접 셀로 이동 |
| Enter | 화면별 기존 업무 흐름 유지. 가격표는 같은 열의 다음 행 |
| Tab / Shift+Tab | 명시적 순서의 다음 / 이전 셀 |
| Esc | 현재 셀의 미확정 편집 취소 |
| Ctrl/Cmd+Z | 화면이 이미 제공하는 실행 취소만 사용. 브라우저의 일반 텍스트 undo를 가로채지 않음 |

방향키는 셀 이동을 우선한다. 셀 경계에서는 숫자 증감이나 커서 이동으로 바뀌지 않도록 키를 소비한다. Tab은 마지막 셀에서 그리드 밖으로 나갈 수 있다.

## 보호 규칙
1. 각 화면이 row, column, order, enabled를 명시한다. DOM 순서만으로 그리드를 추측하지 않는다.
2. 비활성·읽기 전용 셀은 건너뛴다.
3. 현재 입력값을 보존하거나 기존 저장/확정 경로에 전달한 다음 이동한다.
4. 한국어 IME 조합 중에는 셀 이동을 막는다.
5. 비동기 저장 실패 시 기존 초안과 오류 복구 동작을 보존한다.
6. blur는 기존 자동 저장/확정 경로를 유지한다.
7. 상품 선택 후 수량 미확정 상태에서는 수량 확정 또는 상품 선택 취소가 먼저다.

React/TypeScript와 Rust/egui는 같은 계약을 따르되 별도 네이티브 구현을 사용한다. 업무 계산·검증·저장은 기존 Rust 엔진을 유지한다. 소스 검사와 단위 테스트만으로 Windows 실행 검증을 PASS 처리하지 않는다.

## React 공통 이벤트 핸들러

React 화면의 키 이벤트 정책은 `handleCellNavigationKey`로 공통 처리한다. 화면 어댑터는 기존 저장·취소 부수효과만 전달하고, 키 분류·IME 차단·경계 처리·대상 포커스는 공통 모듈이 담당한다.
