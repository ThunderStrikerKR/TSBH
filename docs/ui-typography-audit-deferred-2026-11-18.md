# 2026-11-18 UI 텍스트 전수 분류 조사 및 통합 보류 기록

> **상태: 설계·조사 결과 보존 / 디자인 시스템 통합 보류.**
> 사용자 최종 지시: **기능을 더 다듬은 다음에 디자인 통합을 시도한다. 지금은 기록만 보관한다.**
> 이 문서는 `docs/ui-design-system.md`의 현행 디자인 계약을 대체하지 않는다. 여기의 T0~T8은 추가 검토된 **미적용 제안**이며, `src/ui/design-system.json`의 활성 `typeRoles`을 이미 교체한 것처럼 해석하지 않는다.

## 1. 보류 범위와 우선순위

1. 기존 기능 및 화면 동작 개선을 **우선 수행**한다.
2. UI 전역 리팩터링, 전체 CSS 재정리, 폰트 단계 일괄 변경, 페이지별 컴포넌트 이관은 **사용자가 명시적으로 재개를 지시할 때까지 보류**한다.
3. 기능 수정 중 필요하다면 국소 수정은 가능하지만, 기존 공통 레이아웃 규칙과의 충돌을 확인하고 관련 화면의 동작을 검증한다.
4. 차수가 바뀌어도 본 문서와 `docs/ui-design-system.md`, `src/ui/design-system.json`, `AGENTS.md`를 다시 읽고 완료·보류 상태를 혼동하지 않는다.
5. Windows WebView2에서 실제로 보이는 텍스트의 computed style 검증 없이 **전 화면 UI 통일 완료를 선언하지 않는다**.

## 2. 제안된 공통 T0~T8 텍스트 계층 (아직 미적용)

화면 종류에 따라 별도의 타이포그래피를 만드는 방식이 아니라, **텍스트의 정보 역할**에 따라 적용한다. 색상·상태·인터랙션은 독립적인 다른 축으로 관리한다.

| ID | 역할 | 글씨(px) | 굵기 | 행간(px) | 예시 |
| --- | --- | ---: | ---: | ---: | --- |
| T0 | 브랜드 | 20 | 700 | 24 | BANDO HUB |
| T1 | 페이지 제목 | 20 | 700 | 28 | 상품 관리, 운임 관리, 주문 내역 |
| T2 | 모달/확인창 제목 | 18 | 700 | 26 | 변경사항 저장, 오류 상세, 연결할 카카오톡 선택 |
| T3 | 전역 1차 메뉴 | 16 | 650 | 22 | 접수, 엑셀 관리, 설정 |
| T4 | 주요 섹션 제목 | 16 | 650 | 22 | 발주 원문, 확인할 내용, 처리 중인 주문 |
| T5 | 하위 제목/카드 제목/2차 메뉴 | 14 | 650 | 20 | 거래처명 카드 제목, 설정 하위 탭 |
| T6 | 본문/주요 버튼/입력값/오류 본문 | 14 | 400~600 | 20 | 전화, 상품, 수량, 모달 설명, 조치 지시 |
| T7 | 필드명/표 헤더/소형 작업 버튼 | 13 | 600 | 18 | 주소·수량 레이블, 테이블 컬럼 제목 |
| T8 | 날짜/건수/보조 설명/메타 | 12 | 400~500 | 17 | 알림 날짜, 배송 건수, 부가 설명 |

- T0/T1과 T3/T4의 크기가 같아도 서로 다른 **의미의 역할**이다.
- T6 오류 본문은 T8로 축소하지 않는다. 위험·경고·성공의 의미 색상은 별도 상태 토큰으로 결정한다.
- 금액·수량·KPI의 시각적 강조, 실제 발주 원문(16px 수준), 작은 너비에서의 말줄임/줄바꿈은 **명시적 조합 규칙 또는 검증된 예외**가 필요하다.
- 12px 최소 가독 기준을 목표로 할 경우 `uiScale` 90% 설정에서 폰트가 12px 아래로 줄어드는 문제를 고려해야 한다.
- 역할별 폰트 패밀리, 자간, 숫자 tabular 설정, 최대 줄 수, 오버플로우, 포커스·선택 등은 세부 설계 단계에서 결정한다. **위 숫자는 제안이지 승인된 최종 렌더링 결과가 아니다.**

## 4. 당시 소스 조사 결과 (정적 CSS / JSX, Windows computed style 아님)

- `src/main.tsx`는 `styles/index.css` 외에도 `v0809.css`, `product-admin-redesign.css`, `tauri-stage2-products.css`, `table-density.css`, `management-layout.css`를 추가 로드한다. **파일 로딩 순서 및 선택자 우선순위**가 충돌 가능성의 핵심이다.
- 조사한 스타일시트 **24개**에 `font-size` 속성의 직접 px 수치 표기가 **434건**, 그중 **12px 미만 119건** 확인됨. 과거/중복 규칙도 포함한 정적 선언 건수이므로 실제 표시 글씨의 종류·사용 빈도와 같지 않다. `font` 축약 선언, 변수만으로 정의한 값과 런타임 computed style은 이 숫자에 포함되지 않는다.
- 상단 네비게이션: `src/styles/theme.css`의 `.docked .app-header nav button` **13px**, 기존 기본 **15px**. 제안 T3 **16px**보다 작고 상태에 따라 위계가 달라진다.
- 관리 하위 탭: `src/styles/management-layout.css`의 `.management-tabbar > button` **12px**. 제안 T5 **14px**와 차이.
- 알림 센터: `src/styles/application.css`의 `.notification-center-item strong` **12px**, `small` **10px**. 알림 제목·본문·날짜에 공통 텍스트 역할이 필요.
- 오류 표시: `src/OrderDesk.tsx`, `src/orders/RetailOrderDialog.tsx`, `src/ActualFreightField.tsx`에 `<small className="form-error">` 또는 작은 상태 요소 사용. **HTML 태그가 아니라 오류 의미를 기준**으로 T6 적용 여부를 판단할 것.
- 두 모달 경로: `src/ui/Modal.tsx`의 React `<h2>`와 `src/dialogs.ts`에서 동적 DOM `<h2>` 생성. 같은 T2 역할을 공유하는지 실제 computed style 검증 필요.
- 브랜드: `src/app/AppHeader.tsx`에서 `BANDO HUB`와 `/ 테스트`가 단일 span이다. T0·T8을 별도 적용하려면 UI 소스 변경이 필요.
- 브랜드 오른쪽 띠: `src/styles/patch-v0808.css` **8행 `border-right: 1px solid #454545`** 직접 명시. 사용자가 제거 대상으로 지적했으나 본 조사에서는 제거하지 않음.
- `src/styles/tokens.css`의 신설 `--ds-tableHeader-fontWeight: 600px`, `--ds-tableRow-fontWeight: 400px`는 잘못된 단위. `font-weight`는 단위 없는 값이어야 한다. 현재 미사용 토큰이지만, `scripts/check-ui-design.mjs`는 문자열 일치만 검사해 잘못된 값을 통과시켰다. 추후 통합 전 오류 수정과 validator의 단위 검사 필요.
- `src/ui/design-system.json`은 **2026-11-18 신규 작성**된 파일이다(커밋 `01f095832ec91b0a7d5f92586fe2f16f2be2152b`). 기존 `tokens.css`, `components.css`, `management-layout.css`, `Button.tsx`에 있었던 구 규칙을 자동으로 대체하거나 이미 모든 화면에 적용한 파일이 아니다.
- 현재 전역 UI 분류와 위 T0~T8 제안은 **일치하지 않는다**. 사용자가 통합을 재개할 때 신규 분류를 기존 토큰에 올바르게 이관하고, 오래된 선택자 예외를 제거해야 한다.

## 5. 사용자 지적 사항 보관 (미완료 구현과 구별)

1. 버튼의 **가로/세로 크기, 글씨 대비 내부 여백, 가로·세로 정렬, 동일 역할 규격**.
2. `BANDO HUB / 테스트` 오른쪽의 불필요한 띠와 로고/브랜드 글자 비율.
3. 주요 메뉴는 하위 메뉴보다 시각적으로 중요해야 한다. 현재 상단 네비게이션은 작고 알림/카카오톡 보조 버튼은 과하게 큼. 다른 화면의 페이지·하위 메뉴도 같은 위계를 따를 것.
4. 한 카드의 위/아래 패딩 균등, 동일 컴포넌트의 행 높이·베이스라인 정렬.
5. 사용자 수정 최신 원터치 호버 목표 **250ms**. 당시 코드는 **120ms**여서 별도 기능 개선 항목.
6. 카카오톡 **함께 보기 / 나누어 보기 / 카카오톡 연결 해제**는 **세 독립 버튼** 유지. 순환 모드 버튼으로 변경 금지. 세 버튼 모두 **카카오톡 구역 상단으로 이동**, 마지막 해제 버튼은 더 작은 보조 버튼. 해당 변경은 설계 확정, UI 적용 별도.
7. 카카오톡 하단 광고를 화면 밖으로 밀기 위한 과잉 높이 연장으로 **스크롤바 하단까지 화면 밖으로 밀려난 문제**: 미검증/미완료.
8. 거래처/품목/금액 카드와 폼 정렬 문제 및 오류 메시지 강조의 일관성 문제를 포함하여 **전체 8개 화면을 대상으로 같은 분류**를 적용한다.

## 6. 통합 재개 시 검증 조건 (현재는 수행하지 않음)

- 단일 원본 `design-system.json` → 실제 React 공통 컴포넌트 → CSS 토큰 소비 경로를 검증하고 오래된 숫자/색상 직접 설정을 제거한다.
- UI 요소별 정보 계층(T0~T8), 의미 색상(정상/오류/경고/선택 등), 인터랙션(기본/호버/선택/비활성/처리 중)을 독립적으로 조합한다.
- 접수·주문 내역·엑셀 관리·일일 결산·상품·운임·거래처·설정, 하위 탭, 모든 모달/확인창/알림·오류/개발자 모드를 포함한다.
- 폰트·행간·가로/세로 패딩과 Windows 화면 배율, 긴 텍스트, 좁은 창 상태를 실제 WebView2 computed style 및 스크린샷으로 확인한다.
- `npm run check:ui-design` 및 Windows 테스트를 별도의 증거로 기록한다. 자동 정적 검사만 통과해도 전체 디자인 통합 완료는 아니다.
- **사용자 재개 지시 전: 구현/통합/일괄 CSS 변경 금지.** 이 기록은 설계 결정을 기억시키기 위한 것이며 코드 수정 명령은 아니다.
